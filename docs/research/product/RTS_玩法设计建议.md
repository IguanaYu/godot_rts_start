# RTS 玩法设计建议

> 本文是基于多轮设计讨论得出的完整玩法建议。设计目标是**为 10 分钟一局的 PVE 简化版经典 RTS**——保留 RTS 的核心味道（手动建造、产能扩张、微操），同时降低门槛（简化运营、清晰节奏、容错友好）。

## 一、游戏定位

**简化版经典 RTS，PVE 为主，10 分钟一局**

- **保留** RTS 的核心味道：手动造建筑、兵营产能、空间决策、微操可能性
- **简化** RTS 的痛点：操作繁琐、决策密度过高、APM 门槛
- **目标玩家**：想体验 RTS 张力但不想被人类对手碾压的玩家

**10 分钟一局决定了所有设计选择的优先级**：
- 科技决策总数控制在 4-5 次（不能更多）
- 节奏必须有清晰的断点（玩家不能迷失）
- 容错必须高（玩家没有时间重新开始）

---

## 二、玩家角色

**战地指挥官 + 微操执行者**

玩家完全可以选择并操作每一个小兵。微操是真实存在的——这是 RTS 味道的一部分。指挥官级操作（Y 键全体进攻、集结点）只是便利工具，不是替代微操。

| 操作类型 | 描述 | 是否强制 |
|---|---|---|
| **战略决策** | 造建筑、选目标、规划运营、升本 | 强制 |
| **指挥官级操作** | Y 键全体进攻、集结点设置、释放技能 | 可选（便利工具） |
| **微操** | 选中单位、拉残血、放单位技能、绕后包夹 | 可选（但绝对存在） |

**关键**：Y 键全体进攻和微操是**两层并存**的设计——给高手留微操空间，给普通玩家留简化路径。

## 三、核心循环（10 分钟典型流程）

```
开局（0-2 分钟）—— T1 阶段
   ↓
   造农场补经济 + 造兵营 + 攒钱升本
   ↓
抉择期（2 分钟）—— 升本到 T2
   ↓
中期（2-6 分钟）—— T2 阶段
   ↓
   三选一：升科技 / 攻占据点（开矿）/ 多造兵营（暴兵）
   ↓
转折点（6 分钟）—— 升本到 T3
   ↓
后期（6-10 分钟）—— T3 阶段
   ↓
   决战 / 占领最后据点
```

**关键节奏点**：
- **2 分钟**：第一次升本（T1→T2）—— 第一次大决策
- **6 分钟**：第二次升本（T2→T3）—— 第二次大决策
- **中间穿插**：2-3 次小科技决策 + 多次战斗决策

## 四、建造系统

**完全手动建造，不走图纸/模板路线**

### 设计原则

| 元素 | 设计 |
|---|---|
| 建筑放置 | 玩家手动放置（W 模式建筑放置） |
| 建筑类型 | 兵营、射箭场、修道院、农场、箭塔、墙、城堡、军事学院 |
| 建筑意义 | 兵营是产能节点（持续产出），不是装饰品 |
| 位置决策 | 保留（玩家要思考兵营放哪） |
| 拆建筑 | 退大部分钱（容错） |

### 为什么不做图纸/模板

- **破坏直接控制感**：图纸 = "我下意图，系统执行"，玩家失去"1:1 直接对应"的爽感
- **环世界感**：间接控制是 Base Builder 游戏的特征，不是 Classic RTS 的特征
- **决策同质化**：图纸让"造兵营/升科技/出兵"三个本应不同的决策趋同

详细分析见 [RTS_自动化建造与游戏类型演化.md](RTS_自动化建造与游戏类型演化.md)。

## 五、造兵系统

**红警式 UI + 全局队列 + 集结点**

### UI 层

```
┌────────────────────────────┐
│       造兵面板（侧边）       │
├────────────────────────────┤
│                              │
│  [1] 步兵（25金）           │  ← 兵营造好后高亮
│       ✅ 已有兵营             │
│                              │
│  [2] 弓箭手（40金）         │  ← T2 + 射箭场后高亮
│       🔒 需要 T2 + 射箭场    │
│                              │
│  [3] 僧侣（50金）           │  ← T2 + 修道院后高亮
│       🔒 需要 T2 + 修道院    │
│                              │
│  [4] 骑士（150金）          │  ← T3 + 城堡后高亮
│       🔒 需要 T3 + 城堡      │
│                              │
└────────────────────────────┘
```

- 屏幕侧边**常驻面板**显示所有可造兵种
- **数字键 1-4 直接下单**（不需要先按 Q 进入模式）
- 锁定的灰显但不隐藏（教学价值——玩家看到未来能造什么）

### 系统层

- **全局生产队列**（最多 5 个订单）
- 多兵营**自动并行**（CE2 式，玩家不需要管哪个兵营）
- 钱**下单时立即扣**（红警式）
- 取消订单**退全款**（容错）

### 空间层

- 兵**从对应建筑走出来**（保留因果可见性）
- **自动选建筑**（不需要 Primary 切换）——优先选空闲的、或离集结点最近的
- **右键设置集结点**——兵自动走过去
- 多造同类建筑 = 全局队列生产加速（红警式 Catalyst）

### 关键差异（对比最初的"鼠标位置直接造兵"设计）

| 维度 | 最初设计 | 最终建议 | 理由 |
|---|---|---|---|
| 造兵 UI | Q 模式 + 数字键 | 常驻面板 + 数字键（无 Q） | 减少操作层级 |
| 兵的生成位置 | 鼠标位置（绕过兵营） | 对应建筑走出来 | 保留兵营价值 + 因果可见性 |
| 生产队列 | 无 | 全局队列（5 个） | 兵营作为持续产能节点的必要条件 |
| 多兵营管理 | 玩家手动 | 系统自动并行 | 简化操作 |
| 集结点 | 无 | 有（右键设置） | 释放注意力 |

**为什么不能鼠标位置直接造兵**：
- 绕过兵营 = 兵营失去价值（违反"保留 RTS 味道"目标）
- 破坏空间约束 = 失去"补给线"张力
- 没有产能上限 = 经济曲线失平衡
- 这不是 CE2 的做法（CE2 仍然有建筑即产能）

## 六、科技系统

**3 时代演进 + 每时代少量关键升级**

这是为 10 分钟一局**量身定制**的极简科技设计。

### 设计原则

10 分钟游戏里玩家最多能做 4-5 次科技决策。所以：
- 科技树节点数控制在 5 个以内
- 用**时代演进**（T1→T2→T3）作为主节奏
- 每个时代只有 2-3 个升级选项
- 玩家不需要思考复杂前置依赖

### 三个时代

```
T1（开局就有）──────── T2（升本）──────── T3（升本）
                       500 金              1000 金
                       30 秒               60 秒
```

### 每个时代解锁什么

**T1（0-2 分钟）**：
- 建筑：农场、兵营、墙、箭塔
- 兵种：步兵
- 科技：无（让玩家专注运营和造兵）

**T2（2-6 分钟）**：
- 解锁建筑：射箭场、修道院、军事学院
- 解锁兵种：弓箭手、僧侣
- 科技：军事学院里的 3 个升级（3 选 1 或 3 选 2）

**T3（6-10 分钟）**：
- 解锁建筑：城堡
- 解锁兵种：骑士（或类似强力单位）
- 科技：2 个关键升级（2 选 1）

### 科技升级清单

**T2 阶段（军事学院解锁后）**：

| 升级 | 花费 | 效果 | 送兵 |
|---|---|---|---|
| 步兵强化 | 150 金 | 所有步兵 +20% 攻击 +20% 血量 | - |
| 弓箭强化 | 150 金 | 所有弓箭手 +20 射程 +20% 攻击 | - |
| 僧侣强化 | 150 金 | 僧侣治疗量翻倍 | - |

**T3 阶段**：

| 升级 | 花费 | 效果 | 送兵 |
|---|---|---|---|
| 解锁老兵 | 400 金 | 新造步兵变老兵（强力） | 送 3 个老兵 |
| 解锁骑士 | 500 金 | 城堡可产骑士 | 送 2 个骑士 |

### 总决策数

```
T1: 0 次科技决策
T2: 1-2 次（3 选 1 或 3 选 2）
T3: 1 次（2 选 1）
总计：2-3 次科技决策
```

**这就是 10 分钟游戏的合理决策量**——不多不少，玩家有选择空间但不会过载。

### 关于水科技（小数值升级）

之前讨论过的"100 块加 5 血上限"这种水科技——**在 10 分钟游戏里不建议做**。理由：

- 玩家没时间刷水科技
- 水科技会让决策数量爆炸（玩家算不过来）
- T2 的 3 个强化升级已经覆盖了水科技的功能（经济 sink + 平滑提升）

**如果未来要做长时游戏（30 分钟+），再加回水科技**。

### 科技界面 UI

```
┌─────────────────────────────────────────────────────┐
│                    科技 / 时代面板                    │
├─────────────────────────────────────────────────────┤
│                                                       │
│  [T1] ─────→ [T2] ─────→ [T3]                       │
│   已完成      已完成      升本（1000金，60秒）        │
│              ↑升完                                     │
│                                                       │
├─────────────────────────────────────────────────────┤
│ 当前可用升级（T2 军事学院）：                          │
│                                                       │
│   [步兵强化]    [弓箭强化]    [僧侣强化]              │
│    150 金       150 金        150 金                  │
│    未升          已升           未升                   │
│                                                       │
├─────────────────────────────────────────────────────┤
│ 升级 T3 后解锁：                                       │
│   🔒 老兵（400金）  🔒 骑士（500金）                  │
│                                                       │
└─────────────────────────────────────────────────────┘
```

**设计要点**：
- 横向时代条——T1→T2→T3 一目了然
- 当前可用的居中显示
- 锁定的灰显但不隐藏（教学价值）
- 依赖关系通过位置表达（在 T3 区 = 需要 T3），不需要文字写"需要 T3"

### 军事学院（科技建筑）

- **造价**：350 金
- **建造时间**：30 秒
- **占地**：2x2
- **HP**：800
- **功能**：所有单位升级在这里进行
- **造完后**：UI 栏的科技界面高亮可用

## 七、送兵机制（种子部队）

**建筑首产 + 关键科技突破送少量兵**

### 设计原则

1. **送的兵是"种子部队"**——不能独守，但加上玩家造的少量兵能防守
2. **战力甜区**：送的兵战力 ≈ 第一波敌人的 30-50%（玩家必须自己造兵补足）
3. **首次解锁送，水科技不送**——避免"刷科技堆兵"的反模式
4. **送的兵从建筑走出来**——保留因果可见性

### 送兵触发

| 触发 | 送什么 | 数量 |
|---|---|---|
| 兵营首次建造完成 | 步兵 | 2-3 个 |
| 射箭场首次建造完成 | 弓箭手 | 1-2 个 |
| 修道院首次建造完成 | 僧侣 | 1 个 |
| T3 关键科技（解锁老兵/骑士） | 对应变体 | 2-3 个 |

### 解决的核心问题

- **填补投资真空期**——玩家升科技时不至于完全无兵可用
- **缩短首次反馈链**——新手造完建筑立刻有兵
- **保留 RTS 味道**——建筑仍要造，决策粒度不变

### 为什么不每次升级都送兵

之前讨论过的反模式：每次升级都送兵 = 玩家发现"刷科技堆兵"比正经造兵划算 → 兵营失去意义 → 决策同质化。

详细分析参考 Grubby 的 "Why free units are a BAD IDEA in most RTS games" 批判。

## 八、战斗与指挥

**指挥官级操作 + 微操并存**

### 玩家可做的操作

| 操作 | 工具 |
|---|---|
| 选中单位（单选/框选） | 鼠标左键 |
| 移动/攻击移动 | 右键 / A 键 |
| 全体进攻 | Y 键（便利工具） |
| 设置集结点 | 右键建筑（兵营模式） |
| 释放技能 | 单位技能键 |
| 微操（拉残血、绕后） | 标准 RTS 操作 |

### Y 键全体进攻的定位

- **不是替代微操**，是**便利工具**
- 玩家不想微操时用 Y 键，想微操时手动操作
- 这对应大多数 RTS 玩家的实际玩法（框一圈 A 上去）

## 九、指挥官差异化系统

**重玩性的核心来源**

10 分钟游戏的指挥官应该改的是**节奏**，不是科技内容。每个指挥官改变"什么时候升本"——这是节奏差异。

### 指挥官示例

| 指挥官 | 改的节奏 | 玩法差异 |
|---|---|---|
| **标准指挥官** | （基线） | 标准玩法 |
| **快攻指挥官** | T2 升本便宜 30% | 更快进入 T2 |
| **科技指挥官** | T3 升本便宜 30% | 更快进入 T3 |
| **暴兵指挥官** | T1 兵种强化翻倍 | 不升本也能玩 |
| **精英指挥官** | 兵贵但强，升本送的兵翻倍 | 围绕精英单位 |
| **英雄指挥官** | 开局送一个英雄单位 + 多钱 | 围绕英雄组建军队 |
| **援军指挥官** | 加 A→E 边（击杀返资源） | 以战养战（CE2 Switty 式） |

### 设计原则

- 指挥官改变**运营节奏**，解决"前期 30 秒统一化"的枯燥
- **改图结构 > 改数值**（CE2 教训：数值指挥官边际递减）
- 每个指挥官对应不同的战略风格

## 十、敌方指挥官系统（已设计）

**大小结合的技能节奏**

### 小 buff（判断据点是否好进攻）

- 治疗、护盾、鼓舞等
- 玩家初期侦察时看到这些 → 判断据点特征
- 例：召唤流据点 → 快攻；治疗流据点 → 集火秒杀仪式单位

### 大 buff（30 秒-1 分钟反应窗口）

- 紧急动员、释放驻军、出击、协同等
- 玩家看到据点释放技能 → 知道 CD 窗口 → **清晰的进攻时机**
- 玩家可以选择撤退或硬抗

### 节奏清晰度

这反而让节奏**比经典 RTS 更清晰**——经典 RTS 你不知道对方什么时候来压你，这里你**看到信号就知道**什么时候该攻。

敌方指挥官释放大技能的窗口期 = 玩家进攻的好时机。

## 十一、整体节奏感

```
时间轴：

0s ──── 30s ──── 120s ──── 180s ──── 360s ──── 600s ────→

[运营期]  [抉择期]  [实战期]   [运营期]  [转折点]  [决战期]

造建筑    攒钱      敌人来袭   占据点    升T3     决战
送种子兵  升T2      防守+反攻  升水科技  造城堡   占领最后据点
          造射箭场            
                              ↑
                    敌方指挥官技能释放
                    = 清晰的进攻窗口
```

**节奏特征**：
- 清晰的"运营 → 抉择 → 实战"循环
- 每个阶段玩家心智模式不同（避免认知分裂）
- 敌方指挥官技能释放 = 明确的进攻窗口信号
- 玩家不需要"一边战斗一边回家造塔"的多线撕裂

---

## 十二、要避免的设计陷阱

| 陷阱 | 为什么避免 |
|---|---|
| 图纸/模板建造 | 破坏直接控制感（环世界感） |
| 鼠标位置直接召唤兵 | 破坏兵营价值 + 绕过因果可见性 |
| 每次水科技都送兵 | 异化为"刷科技堆兵"反模式 |
| 兵营没有生产队列 | 兵营退化为单次按钮，价值塌缩 |
| Primary Building 切换 | 增加学习成本，对异质建筑价值有限 |
| 数值 buff 型指挥官 | 重玩性边际递减（CE2 教训） |
| 完全无脑运营 30 秒 | 死时间，重玩性下降（指挥官差异化解决） |
| 复杂科技树（10+ 节点） | 10 分钟游戏玩家没时间体验 |
| 完全无脑的全局升级（影响所有兵） | 没有兵种取舍，决策扁平 |

## 十三、矩阵对照：自家项目 vs CE2 vs RA2

| 维度 | 本建议 | CE2 | RA2 |
|---|---|---|---|
| 主环 | 环 1+2+4（三环咬合） | 环 1+2 强 | 环 1 强，环 4 中 |
| 约束器 | ⚠️ 待加（推荐 Power 式或 Population） | ❌ 无 | ✅ Power |
| 负面关系 | ⚠️ 待加（至少 1 条 Drain 或 Decay） | ❌ 全无 | ✅ Drain+Decay+Block |
| 修饰器 | ⚠️ 待加（推荐 Energy 给指挥官技能） | ⚠️ Randomness | ✅ Info+Energy |
| T 节点 | ✅ 3 时代演进 | ❌ 几乎不存在 | ⚠️ 中（Battle Lab） |
| T2 节点 | ✅ 据点系统 | ✅✅ 极强（核心） | ⚠️ 中（A→T2 弱） |
| 阵营差异 | ✅ 节奏差异 + 图结构差异 | 改数值多 | 盟军改图，苏联改数值 |

**自家项目的优势**：
- T 节点比 CE2 强（有时代演进）
- T2 节点比 RA2 强（据点系统比矿厂有"可占领感"）
- 据点指挥官系统是独有的设计深度

**仍需补全**：
- 约束器（S 节点）—— 给 A 加节奏断点
- 负面关系 —— 至少 1 条 Drain 或 Decay
- 修饰器 —— Energy 给玩家指挥官技能

---

## 总结：一句话描述

**这是一个手动建造、面板造兵、全局队列、集结点指挥的简化版经典 RTS——通过"3 时代演进"控制 10 分钟节奏，通过"种子部队"机制降低投资真空期痛苦，通过"图结构差异化指挥官"提供重玩性，整体节奏由敌方指挥官技能周期和 2/6 分钟升本节点共同构成。玩家是战地指挥官，可以下令全体进攻，也可以精细操作每一个小兵。**
