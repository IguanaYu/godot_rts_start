# RTS 自动化建造与游戏类型演化

> 本文是一份设计讨论记录，源于一个具体想法：**"能不能放一个兵营时自动放一个兵营+一个农场+2个箭塔？或者新建据点时让玩家选前线/后台类型，自动建造对应建筑组合？"**
>
> 这个想法表面是"建造便利化"，深入讨论后发现它触及了 RTS 设计的核心身份问题——**游戏类型的滑动**。本文把这个滑动放到坐标系里分析，并给出三条主流设计路线的取舍框架。
>
> 阅读建议：先看 [RTS 资源转化图分析](RTS_资源转化图分析.md) 建立节点/边/环的词汇，再看本文。

---

## 引言：从一个想法挖到类型问题

原始想法：

> 能不能放一个兵营时，自动放一个兵营、一个农场和 2 个箭塔？或者新建据点时让玩家选"后台发育据点"（自动建造基地+3 个农场）或"前线据点"（自动建造基地+3 个兵营）？

这个想法的第一反应是"代入感会不会不强"。但用资源转化图的框架拆下去，会发现**真正的代价不是代入感，而是图的边属性被集体改写、游戏类型发生滑动**。

---

## 一、手动 vs 预设：本质改写了什么

先抛开"代入感"，看资源图层面发生了什么。

**手动建造**的每一条边（E→P、E→T2、E→S……）的 Trigger 属性都是**主动**——玩家必须按下按钮才触发。这意味着：

- 每条边都是一次**显式决策**
- 每条边都是一次**节奏断点**（强迫玩家抬头看图）
- 玩家对图的"形状"有持续感知

**预设/一键建造**做的事，是把 Trigger 从"主动"改成"自动/条件"——边还在，但玩家不再逐条按。代价是：

**表 1-1：被改写的边/节点属性**

| 属性 | 手动建造 | 预设建造 |
|---|---|---|
| Trigger 触发方式 | 主动 | 自动/条件 |
| Tangible 有形性 | 高（每个建筑都是独立动作） | 中（一组建筑是一个动作） |
| Delay 延迟感 | 强（玩家等建造完成） | 弱（批量进度条） |
| 注意力压力 | 高 | 低 |

**所以这不是"代入感"问题，是图的边属性被集体改写了。**

---

## 二、RTS 的"三头怪"问题

RTS 圈子里有个老命题，叫"三头怪"（three-headed monster）：

```
            经济管理（E）
             ↑
             │
   基地建造（P/T/T2）──── 战术微操（A 操作）
```

任何 RTS 都必须在这**三头**之间分配玩家的注意力。但**玩家注意力是稀缺的**——APM 每分钟就那么多，给这边就给不了那边。

经典 RTS（SC、AoE、C&C）想"三头都强"，结果就是 APM 门槛极高，新人进不来。

后来整个 RTS 品类的演化，本质就是**砍掉一头或两头**：

**表 2-1：RTS 子品类的演化方向**

| 子品类 | 砍了哪头 | 典型作品 |
|---|---|---|
| Classic RTS | 都不砍 | SC2、AoE2 |
| RTT（实时战术） | 砍经济 + 基地 | Company of Heroes 战役、Total War 战斗、Wargame |
| Base Builder | 砍战术微操 | They Are Billions、Iron Marines |
| 大战略 | 砍实时 + 微操 | Stellaris、HOI、Civilization |
| 动作 RTS | 砍基地（只留英雄） | Warcraft 3 |

**"据点预设"的想法，本质上是在动第二头（基地建造）——把它从玩家手里拿走，交给系统。** 问题就变成了：这部分释放出来的注意力，**要让它流向哪里？**

---

## 三、三种可能的流向——对应三种完全不同的游戏

一旦建造被托管，**战斗的形态必须跟着变**，否则游戏会"人格分裂"。三条主流路线：

### 路线 A：流向宏观战略 → 变成"大战略 RTS"

建造全托管 + 战斗也宏观化（小队制、下令进攻方向而非拉扯单位）。

- **玩家心智**：我是个将军，决定打哪儿、什么时候打、用什么兵种配比
- **玩家不做**：拉扯某个单位、补某个建筑、微操某个英雄
- **典型参考**：SupCom（最高指挥官）、Ashes of the Singularity、Total War 战役层
- **核心张力**：决策的"重量"——每个战略决策必须重要，因为玩家没事可做了
- **失败模式**：游戏会感觉"空"，玩家觉得自己在看游戏而不是玩游戏

### 路线 B：流向战斗微操 → 变成"RTT 化的 RTS"

建造托管，但战斗保留甚至强化微操深度。

- **玩家心智**：我是个前线指挥官，基地后勤交给后勤部，我只管打赢这场仗
- **玩家做**：选目标、拉兵线、放技能、利用地形、兵种配合
- **典型参考**：Warcraft 3（极简化基地）、Company of Heroes、Dawn of War
- **核心张力**：战斗必须有足够的深度——能掩护、能压制、能突破、能反制
- **失败模式**：如果战斗还是"两队兵 A 上去"，玩家会觉得"那我干嘛要点建造"

### 路线 C：两边都要 → 回到 Classic RTS 但简化

不全托管，只是半自动（队列、模板、推荐）；战斗也保持中等微操深度。

- **玩家心智**：我还是个 RTS 玩家，但游戏对手不要求我 300 APM
- **典型参考**：AoE4、Iron Harvest、Stormgate
- **核心张力**：平衡——两头都要照顾，两头都不能太深
- **失败模式**：两头都做不深，深度玩家觉得"软"

**这三条路线不是连续的光谱，是三个不同的物种。** 必须选一个，否则游戏会"既不像 A 又不像 B"——这是很多 RTS 死掉的原因。

## 四、因果可见性：经典 RTS 的隐性原则

原讨论中提到一个直觉：**"很怕有什么东西不是从建筑、单位身体里出来的（比如三选一科技这种，从天而降的）"**。

这个直觉非常准。RTS 设计里这叫**因果可见性（Causal Visibility）**，是经典 RTS 几乎不可违背的原则。

**经典 RTS 里所有游戏事件都有可见的物理来源**：

**表 4-1：因果可见性的典型案例**

| 事件 | 来源（可见的因果链） |
|---|---|
| 一个枪兵出现 | 从兵营里走出来 |
| 一笔金币到账 | 矿工从矿区走回基地 |
| 一项科技解锁 | UI 进度条走完 |
| 一个技能释放 | 单位身上有动画 |

**违背这个原则，玩家会本能反感**。"三选一科技从天而降"就是典型反例——红警 3 的科技协议、C&C 系列将军能力、帝国时代 4 的 landmark bonus，都有这种"凭空出现"的感觉。玩家不讨厌这些功能本身，讨厌的是**因果链被切断了**——不知道这玩意儿哪来的。

### 4.1 回到预设建造

"我选了前线据点，然后系统自动造了 3 个兵营"——这里**兵营的来源被抽象掉了**。玩家看到 3 个兵营"长出来"，但不知道是谁造的、怎么造的、为什么这么快。这正是潜意识觉得"代入感不强"的真正原因。

但**这个原则可以保留**——只要给预设一个**可见的执行者**：

**表 4-2：预设建造的因果可见性保留程度**

| 设计选项 | 因果可见性 | 说明 |
|---|---|---|
| 选模板后系统凭空造出建筑 | ❌ 切断 | 你讨厌的"从天而降" |
| 选模板后有个"工兵单位"跑去建造 | ✓ 保留 | 工兵是来源 |
| 选模板后建筑以"打包形态"空投下来 | ✓ 保留 | 空投是来源 |
| 选模板后显示建造队列+进度条 | △ 部分保留 | 时间是来源 |
| 预设是指挥官技能，有能量消耗+动画 | ✓✓ 保留 | 指挥官是来源，能量是成本 |

**最后一种最值得做**——因为预设**进入了资源图本身**，不再是悬空的 UI 功能。这对应[资源转化图分析]的关键洞察 4：**功能作为图的一部分，比作为便利按钮更有设计价值**。

## 五、决策没消失，是被搬运了

[资源转化图分析]关键洞察 3 说"运营决策 = 在四个环之间分配资源"。预设不会取消这个决策，只会把决策的**位置**搬走。

- **全手动**：决策发生在"造第几个兵营""什么时候补农场"——**微观层**
- **全预设**：决策发生在"这个据点是前线还是后台"——**宏观层**

"选前线据点 / 后台据点"本质上是把图里**环 2（军力-地盘）和环 1（经济自催生）的选择**，从玩家造建筑那 30 秒，前移到了"开分矿那 1 秒"。

这有好有坏：

**好处**：新手终于能玩懂了。他们不用懂"什么时候该补第 3 个兵营"，只需要懂"我要打进攻还是要发育"——这是更**抽象但更直觉**的决策层。

**坏处**：决策密度被压缩。原来 30 秒里玩家做了 5 次运营决策，现在变成了 1 次。RTS 一部分"好玩"是来自**决策密度本身**——脑子的忙碌感。密度过低，玩家会"没事干"。

---

## 六、节奏断点：消失还是变形？

节奏断点不是消失了，是**从建造侧转移到了选择侧**。

**表 6-1：节奏断点的迁移**

| 节奏断点类型 | 全手动 | 全预设 |
|---|---|---|
| 微观断点（补人口、补兵营） | 多 | 几乎没有 |
| 宏观断点（选什么据点） | 少 | 每次开分矿一次 |
| 失败归因 | 清晰（"我没补人口"） | 模糊（"我选错据点类型了"） |

**失败的归因模糊**是预设最大的隐患。玩家输了之后，全手动可以复盘"哦我 8 分钟该补农场没补"，预设就只能复盘"我开局选错了"——后者更**致命也更难学**。新手被 punish 一次之后可能直接弃游。

## 七、设计路线决策树

把所有维度合在一起，得到这张决策树：

```
                  你这个 RTS 的核心爽点是什么？

                          │
        ┌─────────────────┼─────────────────┐
        ↓                 ↓                 ↓
   "我打赢了一场         "我的布局           "我的操作秀翻
    史诗战役"            无懈可击"           了对手"
        │                 │                 │
        ↓                 ↓                 ↓
    大战略 RTS          Base Builder      Micro RTS
   (SupCom 路线)       (塔防化 RTS)     (War3 路线)
        │                 │                 │
        ↓                 ↓                 ↓
   全预设合理          全预设核心        不预设或半预设
   战斗也宏观化        战斗也宏观化      战斗深度化
   因果靠"指挥官"      因果靠"工兵"      因果靠"建造过程"
```

**注意**：这三条路线，**预设扮演的角色完全不同**：

- 在大战略路线，预设是**核心玩法**——玩家做的就是宏观决策
- 在 Base Builder 路线，预设是**加速器**——让玩家更快进入塔防节奏
- 在 Micro RTS 路线，预设是**反设计**——它剥夺了玩家学习运营图的机会

## 八、半预设的中间路线

如果不想走极端，还有几种半预设方案值得权衡：

### 选项 A：模板 + 自由覆盖

选"前线据点"自动铺 3 兵营 + 基地，但玩家随时可以拆掉 1 个换箭塔。

- **张力**：给了脚手架，但脚手架太好用 → 玩家懒得自己思考

### 选项 B：预设建造队列（节奏保留）

选模板后系统**自动排队建造**：基地 → 兵营 → 兵营 → 兵营，玩家看到进度条。建造过程保留时间感，但 APM 释放了。

- **张力**：建造途中被攻击怎么办？队列能打断吗？

### 选项 C：推荐而非自动（UI 引导）

UI 显示"前线据点推荐配置：3 兵营 + 1 农场"，但实际建造还是玩家手点。

- **张力**：UI 信息量大，老手嫌烦

### 选项 D：指挥官/种族差异化（差异化切口）

只有**特定指挥官**能一键部署，作为种族差异。比如"工程师指挥官"能模板化建造，"指挥官将军"必须手动建造但兵更强。

- **张力**：这其实就是关键洞察 4（种族差异 = 改图结构）——预设作为一种**结构差异**而不是普适功能

### 选项 E：模板作为"科技解锁"

开局不能预设，必须**手动造过 N 次同一组合**后，才能解锁"一键部署"。

- **张力**：解决"学习中断"问题——玩家先学会走图，再用预设提效

## 九、关键判断：游戏身份的统一性

最危险的状态是**"建造宏观 + 战斗微观"——玩家脑子会分裂**。

如果一个 RTS：

- 据点占领是宏观的（走过去就占领）
- 建造是预设的（选模板自动生成）
- 但战斗还要玩家拉扯每个单位

那玩家会陷入认知失调：**"我到底是将军还是士官？"** 这种分裂状态比任何单一方向的极致化都更伤害游戏。

**反过来**，如果承认向宏观方向滑动，那就该：

1. 建造宏观化（模板/预设）
2. **战斗也对应宏观化**（小队制、自动掩护、下令而非拉扯）
3. 节奏感由"战略决策断点"（什么时候开矿、什么时候转型、什么时候 all in）承担
4. 因果可见性通过**执行者单位**（工兵、指挥官、空投船）保留

这样整个游戏节奏统一，玩家心智一致——**我是个将军，不是个 микромanager**。

## 十、需要回答的核心问题

在做任何关于预设/自动化的决定之前，先回答这几个问题：

### Q1：核心爽点定位

你这个 RTS 最想让人记住的瞬间是什么？

- **"我打赢了一场史诗战役"** → 大战略 RTS（SupCom 路线）
- **"我的布局无懈可击"** → Base Builder（塔防化 RTS）
- **"我的操作秀翻了对手"** → Micro RTS（War3 路线）

三种答案对应三种完全不同的设计。

### Q2：玩家 APM 画像

你的目标玩家 APM 大概在什么水平？

- 100 APM 以下：基本玩不了 SC2，但能玩 AoE4
- 50 APM 以下：只能玩 Base Builder 或大战略

这个数字决定了**必须砍掉哪一头**。

### Q3：因果可见性原则

游戏里现在有没有"从天而降"的元素（如三选一科技、将军能力）？

- 如果有：因果可见性已经被破坏过一次，预设只是第二次破坏
- 如果没有：说明你在意这个原则——那预设就必须想办法保留因果链

### Q4：整体方向校验

你的据点系统、指挥官系统、占领机制——这些**已经是比经典 RTS 更宏观**的设计了吗？

如果据点本身就是战略单元，那预设建造其实是**顺应**这个方向，不是背叛。但战斗层面也必须对应调整。

## 附：设计选项速查

| 设计选项 | 适用路线 | 因果可见性 | 决策密度 |
|---|---|---|---|
| 全手动建造 | Micro RTS | 高 | 高 |
| 半预设 + 自由覆盖 | Classic RTS 简化 | 中 | 中 |
| 预设建造队列 | Classic RTS 简化 | 中 | 中 |
| 推荐配置（不自动） | 全路线通用 | 高 | 高 |
| 指挥官差异化预设 | 大战略 RTS | 高（有能量来源） | 低 |
| 全预设 + 工兵执行 | 大战略 / Base Builder | 高（工兵可见） | 低 |
| 全预设 + 凭空生成 | ❌ 不推荐 | 低 | 低 |

## 总结

**自动化建造不是"便利化"问题，是游戏类型选择问题。**

- **手动 vs 预设** 改写的是图的所有边属性（Trigger/Tangible/Delay）
- **建造方式** 必须和**战斗方式**统一，否则玩家心智分裂
- **因果可见性** 是经典 RTS 的隐性原则，预设必须想办法保留它
- **决策不会消失，只会被搬运**——从微观层搬到宏观层，密度下降但单次权重上升
- **三条路线是三个物种**：大战略 / RTT / Classic RTS 简化，必须选一个

最重要的判断：**先确定游戏身份（爽点定位 + 玩家画像），再决定建造方式**。反过来做会陷入"既不像 A 又不像 B"的死亡区。
