## 一、案例事实（先穷举各引擎/产品怎么做的）

### 1. Godot 4（本项目引擎）——没有引擎级"画廊"，但有可复用的能力

- Godot 4 **没有** Unity 那样的独立粒子预览面板。编辑器里 GPUParticles2D 只要 `emitting=true` 就在编辑视口直接播放，改检查器参数即时可见——但它依赖"放进场景"，无法脱离场景单独预览一个特效。
- 官方有 `EditorResourcePreviewGenerator` API（[Godot 文档](https://www.bookstack.cn/read/godotengine-3.3-zh/94e52e5d47c8bff5.md)）可为自定义资源生成静态缩略图——**对动态粒子基本没用**（见试错教训 1）。
- 社区惯例：godot-shaders 这类库（[可播放演示版](https://download.csdn.net/download/weixin_42098104/15906050)）是**每个 shader/特效一个独立演示场景**，靠"跑场景"看效果——本质上就是"特效即场景"。
- 官方 GPUParticles 4.0 改进（[godotengine.org](https://godotengine.org/article/improvements-gpuparticles-godot-40)）：新增 Manual Emission 等能力，意味着粒子可由脚本精确控制发射——对"点一下播放一个特效"是利好的。

**本项目已具备的资产清单来源**（画廊目录的数据底座）：

| 清单 | 来源 | 内容 |
|---|---|---|
| 粒子配方库 | [ParticlePool](../../../scripts/effects/particle_pool.gd) | dust / explosion / hit_spark / debris / energy_fog / heal_orb / blood_mist / dust_gpu …（9 种配方） |
| 技能视觉 | [SkillVisualController](../../../scripts/skills/skill_visual_controller.gd) | 波纹环 / 光柱 / 蓄力环 / screen_impact（8 技能已接入） |
| 屏幕后处理 | [PostProcessController](../../../scripts/effects/post_process_controller.gd) | shake / 色差 / 冲击波 |
| 现有沙盒 | [effect_sandbox.tscn](../../../scenes/sandbox/effect_sandbox.tscn) / [sandbox_controller.gd](../../../scripts/sandbox/sandbox_controller.gd) | **"事件触发型"**：点按钮→特效在世界坐标出现一次。不是"画廊浏览型"（点条目→循环播放+调参） |

### 2. Unity——引擎内置"预览面板"的标杆

官方文档确认（[Unity Particle System 手册](https://docs.unity3d.com/cn/current/Manual/PartSysUsage.html)）：

- 选中粒子系统的游戏对象时，**Scene 视图出现小型浮动 "Particle Effect" 面板**：**Playback Speed**（快/慢放）、**Playback Time**（可拖动 scrub 前后回放）、**Particle Count**（粒子计数）、顶部 **Pause / Resume / Stop+Reset** 按钮。**不需要运行游戏**，纯编辑器内预览。
- 另有独立 **Particle System Editor** 窗口（Inspector 里 "Open Editor"），可同时编辑多个系统。
- Unity VFX Graph 自带预览视口（参数改完自动编译重放）。
- 官方开源 **VFXToolbox**（[GitHub/Unity-Technologies/VFXToolbox](https://github.com/Unity-Technologies/VFXToolbox)）——但它是**资产制作工具**（flipbook 贴图板拼合/重定时、Houdini PCache→VFX 导出），不是画廊。

### 3. Unreal Niagara——"特效编辑器内预览"的最完整范式（最该抄的）

[Niagara Editor 界面拆解](https://blog.csdn.net/weixin_30691649/article/details/161351976)，其**预览面板（Preview Viewport）**是一块独立于游戏场景的画布：

- 右键旋转 / 中键平移 / 滚轮缩放 / Alt+右键调 FOV
- **网格背景开关**（专业特效审查标准背景）
- 空格重置视角 / **F 聚焦**当前发射器
- 右下角**帧率显示**（性能红线提示）
- **Timeline**：暂停 / 播放 / 单帧步进 / 循环

→ 打开一个 Niagara System 文件即进入独立预览，改参数实时看，**不污染游戏场景**。这是"预览图级别浏览体验"的业界答案。

### 4. 独立粒子编辑器——"特效库 + 画廊"产品化参照

- **TimelineFX Particle Editor**（[GitHub/peterigz/timelinefx](https://github.com/peterigz/timelinefxlib)）：独立粒子编辑器，自带**特效库（Effects Library）**，双击即预览，纯 C 库可嵌入游戏。交互范式 = "一个界面管一堆特效、点开即看"，与本次画廊目标同构。
- **AE FXConsole**（[VideoCopilot 免费](https://www.lookae.com/fxconsole-105/)）：特效管理控制台，最有启发的一点是 **Snapshot 快照图库**——自动保存多个**静帧快照**横向对比、从图库取色、导出 PNG。这是"**抓图对比**"而非"循环播放"的画廊变体。

### 5. 游戏内"技能图鉴/展示"

- 主流 RPG 游戏内技能展示是 **hover tooltip 式**（[UGUI 技能详情 UI](https://zhuanlan.zhihu.com/p/551649872)）：鼠标悬停→文字详情，**几乎不做动态预览**——因为运行时动态预览成本高、且特效属于"战斗反馈"不适合放图鉴。
- Unity 角色展示 UI 用 **RenderTexture + 专用相机渲染到 RawImage**（[教程](https://blog.csdn.net/xyj_sunshine/article/details/78723699)）——Godot 等价物是 **SubViewport + ViewportTexture**，是"一屏多卡片、每卡片循环播特效"的技术手段，但每卡片一份独立渲染，成本随卡片数线性涨。

## 二、试错教训（从调研 + 项目经验反推）

1. **静态缩略图对动态特效没用。** `EditorResourcePreviewGenerator` / contact sheet 批量截图，对粒子、光柱、波纹这类**时变特效**一张图体现不了——必须动态预览。Niagara 能播放、Unity 能 scrub，核心都是"动的"。
2. **预览必须走游戏真实渲染**，不能用编辑器静态预览。项目刚踩过坑：GPU 粒子 color_ramp 不生效导致全白（见 [TODO 已完成区](../../../TODO.md)）——这类渲染器细节只有跑真实场景才能暴露。所以画廊的预览台要**复用同一渲染管线**（同 Camera 设置、同 z_index 规则），否则"画廊看着好、游戏里翻车"。
3. **别直接往现有 effect_sandbox 堆。** 它已堆了 30+ 顶栏/左面板按钮（[sandbox_controller.gd](../../../scripts/sandbox/sandbox_controller.gd)），是"调试台"不是"画廊"。画廊是另一种交互模型（目录→循环预览→调参），混在一起会越改越乱。
4. **Godot 没有引擎级画廊工具**——这个需求在 Godot 生态里本来就得自己造，不存在"装个插件白嫖"的捷径（搜遍 Asset Library 相关只有粒子库/演示场景，没有通用画廊 addon）。

## 三、新增方向（结合 TODO 里 4 条路径的收敛结论）

| 方案 | 形态 | 参照 | 成本 | 适合 |
|---|---|---|---|---|
| **A. 单预览台画廊**（推荐） | 在沙盒加"画廊模式"：左=目录（粒子/地面环/光柱/波纹/后处理/技能组合），右=固定预览台（干净背景+参考单位+网格），点条目循环播放，参数面板滑杆/取色实时调；带 Unity 式 Playback 速度/暂停/重置 | Niagara Preview + Unity Particle Effect 面板 | 中 | "预览图级浏览 + 调参决策" |
| B. 独立图鉴场景 | 脱离沙盒，SubViewport 一屏多卡片循环播 | RenderTexture 卡片 / Art Book | 高（每卡一份渲染） | 后期做成"图鉴/成就"功能或 PR 交付展示 |
| C. contact sheet 截图 | @tool 脚本逐个触发+逐帧截图拼图 | AE FXConsole Snapshot | 低 | 当**导出功能**（把预览台导出 png/gif 序列）放 A 里做 |
| D. 配置导出 | 画廊调好的参数→导出 .tres/json 片段 | TimelineFX 保存 | 低 | 玩家调完 AI 照抄落地，缩短反馈环 |

**结论建议**：**A 为主，C/D 作为 A 的导出子功能**。B 不做第一版。

## 四、待决策思考点

1. **画廊放哪**：effect_sandbox 加"画廊模式"（Tab 切换，不污染现有调试 UI）vs 独立 .tscn 场景？倾向前者（资产清单已在沙盒，复用最多）。
2. **目录数据源**：ParticlePool 配方 + SkillVisualController 技能 + PostProcessController 后处理三套，怎么统一成一份 gallery catalog 配置？需要新配置文件吗？
3. **预览台背景**：Niagara 式浅色网格（业界标准，利于看颜色/响度）vs 项目草地背景？直接关系能否对照 [游戏视觉设计准则](../../standards/游戏视觉设计准则.md) 验收，建议浅灰网格。
4. **参数暴露范围**：第一版只做 颜色/尺寸/时长 够不够？要不要把"响应放大倍数"做成预览台滑杆（项目偏好：微动画幅度要放大 2.5~6 倍才可辨，见记忆 `feedback_vfx_impulse_magnitude`），画廊应能快速试不同放大倍数。
5. **后处理类**（shake/色差/冲击波）是**全屏**特效，预览台局部放不了——要不要做"全屏预览模式"按钮？
6. **配置导出**（D）第一版就做还是后加？
