# 角色拆件与模块化动画调研（Paper Doll / 分部件拼合）

> 调研日期：2026-08-16
> 起因：AI 生成整张精灵表质量不行，提议「身体/脑袋/左右手/武器分开生成，游戏里拼合 + 分部件控制做动画」。
> 结论先行：**这个思路是业界成熟方案**，名字叫 paper doll / modular character / cutout（木偶）动画。
> 它恰好绕开我们实测的 CogView 短板（多帧一致性 ❌、单张静图 ✅）——部件全是**单帧静图**，动画交给代码。

可信度标注：[A] 多源确认/已实测，[B] 单源/强推断，[C] 猜测待验证。

---

## 一、业界定位：这不是新发明

| 名词 | 含义 | 代表 |
|---|---|---|
| Paper doll | 角色 = 分层部件拼合，装备即换层 | Diablo 2 的装备纸娃娃 |
| Modular character | 部件库 + 程序拼合，一套动画通吃所有组合 | **LPC Universal Spritesheet Generator** |
| Cutout / puppet 动画 | 部件挂骨架/挂点上做 transform 动画 | Flash 时代游戏、Spine 生态 |
| 程序化部件动画（无帧动画） | 静态部件 + 代码摆动 | **RimWorld**（殖民者 = 分层静图 + 代码摇摆）、Starbound（分层拼合角色） |

最贴我们场景的两个先例：

- **LPC 生成器**（[sanderfrenken 维护版](https://sanderfrenken.github.io/Universal-LPC-Spritesheet-Character-Generator/)）：社区按统一规范画部件（身体/头/发型/盔甲/武器），程序拼合成完整精灵表。**十年验证了「部件库+拼合」能规模化**。它拼完还是输出帧表，我们更进一步：直接在引擎里部件化。[A]
- **RimWorld**：小人 = 身体+头+发型+衣装分层静图，行走摆动、手臂晃动全是代码驱动，没有任何逐帧动画。**RTS 镜头尺度下完全够看**。这正是你设想的方案。[A]

## 二、与我们现状的契合度

项目现状（已核查，`scripts/units/unit.gd` + `scenes/units/unit.tscn`）：

- 渲染 = 单个 `Sprite2D`（BodySprite）+ `hframes` 切横条表，`_set_anim()/_update_animation()` 手动步进帧（`unit.gd:419-475`）。没有 AnimatedSprite2D / AnimationPlayer / Skeleton2D。
- **单朝向**（素材朝右下），全项目无 `flip_h`。
- 40+ 单位场景实际复用 4 套美术（warrior/archer/lancer/monk × 阵营目录），靠 stats/scale/`variant_tint` 区分。
- `unit_visual_feedback.gd` 已经在做**位移/缩放冲量**（攻击前探、受击位移、缩放脉冲）——等于已经证明了 transform 动画在我们的镜头尺度下可读。

契合点：
1. 动画状态机（idle/run/attack）本来就在代码里，换成部件驱动只是把「步进 frame」换成「摆动部件」，对 `unit.gd` 是小改。
2. 「一套 rig × N 武器 × 调色 = N 兵种」直接解决我们 40+ 单位共用 4 套美术的多样性问题。
3. 与 Tiny Swords 现有帧表单位可以共存（都是 Sprite2D），不用推倒重来，新单位逐步用拆件。

## 三、AI 生成部件的三条路线

### 路线 A：整图生成 → 切片拆件（推荐起步）

先让 AI 生成**拼装好的完整单角色**（3/4 视角、纯色/简单身体——CogView 实测能做），再切成部件、定义锚点。

- 一致性天然有保证：所有部件来自同一张图（和地砖「抠块拼接法」同理）。
- Reddit r/aigamedev 上有同款 pipeline：先生成整体角色，再分离出头/躯干/上下臂/上下腿用于绑定。[B]
- 我们已有资产：CogView 单角色 prompt 模板（pixel-forge `ai-art-guide.md`）、`--quantize` 降色、切块脚本经验。
- 武器可以单独走「武器表抠块」：AI 生成一张排满武器的图 → 切块 → 换装，复用地砖抠块思路。

### 路线 B：部件分别直接生成

每个部件独立生成（小画布、模板 prompt、锁色板、统一降色）。

- 优点：画布小、迭代快、部件数量扩展容易。
- 风险：**跨图风格漂移**（线宽/色阶/比例不一致），CogView 无 negative prompt、无成熟 img2img 锁图流程，prompt 约束边际有限（实测结论）。
- 对策：统一 prompt 后缀 + 同色板 + `qa_check --sprite` 像素级 QA + GLM 视觉抽检（避开 429 高峰）。
- 适合：与路线 A 混用——身体走切片，武器/盾牌等小件走单独生成。

### 路线 C：3D 模型预渲染成精灵表（AoE 传统）

Blender 建模绑定 → 8 方向渲染 → 拼表（[Sorceress 3D-to-2D](https://sorceress.games/pages/3d-to-2d) 这类工具可自动化）。Age of Empires 系就是这条线。

- 优点：多朝向 + 真动画一致性彻底解决。
- 缺点：需要 3D 能力，画风会偏离 Tiny Swords 手绘感，投入最大。**不建议现在走**，记为备选。

### 现成 AI 工具盘点（补充自研 CogView 流水线）

| 工具 | 定位 | 备注 |
|---|---|---|
| [Retro Diffusion](https://retrodiffusion.ai/) | 像素风底图生成 | 社区公认出底图最好 [B] |
| [PixelLab](https://www.pixellab.ai/) | 旋转/动画/sprite sheet | 与 RD 互补：RD 出底、PL 出方向和动画 [B] |
| [Layer.ai](https://www.layer.ai/) | 训画风 + 批量 sprite | 商用工作室向 |
| [Textoon](https://dl.acm.org/doi/10.1145/3746059.3747707)（论文） | 文本→分层 2D 角色 | 学术方向，可关注不可依赖 |

## 四、游戏内合成与动画（Godot 蓝图）

### 节点结构（最小方案）

```text
Puppet (Node2D)                # 整体 flip_h / variant_tint / 缩放
├─ ArmBack  (Node2D)           # 后臂，pivot=肩
│  └─ HandB  (Sprite2D)        # 后手武器，pivot=握把
├─ Torso    (Sprite2D)         # 躯干，pivot=髋
│  └─ Head   (Sprite2D)        # 头，pivot=颈，独立滞后摆动
└─ ArmFront (Node2D)           # 前臂（绘制顺序在躯干前）
   └─ HandF  (Sprite2D)        # 主武器
```

- **锚点即节点**：pivot 不用 JSON 清单，直接固化在 Godot 场景节点 offset 里，每个兵种一个 puppet 场景。武器换装 = 换 `HandF.texture`。
- 挂武器到手上用父子节点即可（RemoteTransform2D 是骨架方案才需要）。

### 动画驱动：纯代码（推荐），不要上 Skeleton2D

| 方案 | 评价 |
|---|---|
| 纯代码摆动（sin 摆、tween 挥砍） | ✅ 推荐。与我们现有代码风格一致，参数即手感 |
| AnimationPlayer 关键帧 | 可选，适合复杂演出；小单位日常动作用代码更顺手 |
| Skeleton2D + Polygon2D 网格变形 | ❌ 不建议。Godot 论坛实例：多朝向 turnaround 折磨到楼主放弃、花 $370 买 Spine；DragonBones 已停更。我们小单位用不到网格变形 [B] |

代码动画草案（对应现有三态）：
- idle：躯干 `position.y = sin(t*2)*1px` 呼吸起伏，头轻微滞后；
- run：起伏加倍 + 双臂交替摆 ±20° + 头反向滞后（RimWorld 同款观感）；
- attack：前臂 tween 旋转挥砍弧 + 躯干前探（前探已被 visual_feedback 验证过）；
- death：整体旋转倒下 + fade（接现有死亡特效路径）。

### 像素画特有注意事项

1. **旋转会破坏像素网格**（亚像素/锯齿）。对策：优先位移/缩放/挤压拉伸；必须旋转时限定小角度，或角度步进（每 15° 一档）。单位在屏幕上只有 ~48px，容错比立绘高得多。[B]
2. **绘制顺序**：攻击时前臂/武器要在躯干之上，后臂在之下——用节点顺序天然解决；左右镜像时前后臂语义互换，注意交换。
3. `flip_h` 建议放在 Puppet 根节点一次搞定，别逐部件翻。
4. 想要描边可以用 `CanvasGroup` + shader（社区常用做法）。

## 五、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 部件间风格/比例漂移 | 高 | 路线 A 起步（同图切片）；QA 用 `qa_check --sprite` + 肉眼 |
| 锚点对不齐，动作穿帮 | 高 | 锚点固化在场景里；sandbox 里做锚点校验姿态（T-pose 式参考帧） |
| 动画感「提线木偶」 | 中 | 镜头尺度小 + 挤压拉伸 + 头部滞后可大幅缓解；不行再给躯干 2-3 帧 |
| 与 Tiny Swords 帧表单位混搭违和 | 中 | 同色板同降色口径；先只给新兵种用，肉眼对比拍板 |
| 工作量转移（拼装调参代替画帧） | 中 | 一套 rig 摊到 N 兵种上就回本；weapon 抠块法扩展便宜 |
| CogView 画风到不了 Tiny Swords 精度 | 中 | RD/PixelLab 付费工具兜底；或 AI 出草稿 + Aseprite 手修关键件 |

## 六、建议验证步骤（一个 PR 的大小）

1. `scenes/sandbox/` 新建 `puppet_demo.tscn`（旁挂 style_demo 旁边）。
2. CogView 整图生成一个 3/4 视角兵种 → 降色 → 切成 躯干/头/双手臂/武器 → 摆进 Puppet 节点。
3. 写 `puppet_animator.gd`：idle/run/attack 三态代码动画，接口对齐现有 `_set_anim()` 语义。
4. 并排放一个现有帧表单位同场行走/攻击，录对比图。
5. **用户肉眼拍板**（pixel-forge 规则 3：用户 > 指标）。

预估：代码 1-2 天 + 首个兵种素材 1 天。通过后再铺管线（weapon 抠块器、兵种 puppet 工厂、`unit.gd` 接入开关）。

## 七、结论

- 你的方案 = RimWorld/LPC 验证过的成熟路线，且与「AI 单帧强、多帧弱」的能力边界正好互补。[A]
- 推荐组合拳：**整图切片（身体） + 抠块（武器） + 纯代码动画（引擎内）**，Skeleton2D/Spine 暂不需要。
- 对本项目的额外红利：一套 rig × N 武器 × 阵营调色 = 低成本铺满 40+ 单位的外观差异。

## 八、首个验证单位实测（2026-08-16，已跑通）

**产出**（全部在库）：`scenes/sandbox/puppet_demo.tscn` + `scripts/sandbox/puppet_unit.gd`（rig+动画器）、
`sheet_unit_demo.gd`（帧表对照）、`assets/sandbox/puppet_unit/{blue,red}/`（五部件 + parts_report.json 锚点报告）。
运行：Godot 打开 `scenes/sandbox/puppet_demo.tscn`，三站并排（帧表 Warrior / 拆件蓝 / 拆件红），
同时间轴循环 idle→run→attack×2；`--shot` 出 tmp/ 截图三张。

**实测结论（重要，修正第三节路线优先级）**：

1. **CogView 生成结构化角色整图失败率 5/5**：小比例全身 + 白底 + T-pose 张臂这类「结构性 prompt」
   产出全部畸变（兜帽巨像满幅、软渐变量化成大片 shadow 色、底部带地台）。比建筑单体难一档。
   → 路线 A（整图→切片）在 CogView-3-flash 上**当前不可行**；换更强生图模型（RD/PixelLab 类）时可重试。
2. **兜底：代码手绘部件完全可行**（pixel-forge 铁律「AI 做不了的代码画」）：`tmp/draw_unit.py`
   用 Tiny Swords 实测色板 PIL 绘制五部件（盔/躯干/双臂/剑），自动外描边 + 阵营重映射，
   秒级重跑迭代，画风一致性 100% 可控。**部件生成优先级改为：代码手绘 > AI**。
3. **引擎侧全部验证通过**：Rig 节点方案（原点=脚锚点）+ 锚点 JSON 数据驱动装配 + 三态代码动画；
   像素实测尺寸与源图 0.6 缩放完全吻合（w34×h58），攻击帧武器挥砍、run 帧摆臂起伏、
   红/蓝同 rig 换色一次到位。
4. **踩坑记录**：① 动画代码里绝对不要写 `_head.position.y = 0` 这类「绝对复位」——锚点偏移会被
   每帧抹掉（表现为头陷进胸腔、身高压扁 40%，视觉模型还报「正常」，再次印证肉眼+像素工具双检的必要）；
   ② 装配根节点必须以脚锚点为原点，否则站位整体偏移；③ 淡彩像素角色在绿草地上做像素检测时，
   阈值要按调色板逐色算，统一阈值会把混色像素全判成草地。

**下一步建议**（按收益排序）：
- 武器抠块器：一张武器排图 → 切块 → 挂手锚点（换装卖点）；
- `unit.gd` 接入开关：puppet 作为 BodySprite 的替代渲染路径，复用现有 `_set_anim` 状态机；
- 兵种 puppet 工厂：draw_unit.py 的 LAYOUT 参数化，N 套兵种部件批量产出。
