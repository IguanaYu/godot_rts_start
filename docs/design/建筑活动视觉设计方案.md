# 建筑活动视觉设计方案

## 目标

在不增加建筑拆分贴图或逐帧建筑动画的前提下，让当前的像素风 RTS 建筑在生产、施工、升级、产金和受击时具备清楚且有重量的世界内反馈。

本方案服务于目前的单张建筑精灵资产，不改动生产、资源、联网同步或战斗判定。

## 现状与约束

- 建筑本体均为单张静态 `Sprite2D`；不假设门、旗帜或屋顶有独立贴图。
- 可复用：`assets/effects/Dust_01.png`、`Dust_02.png`、出生光柱、爆炸序列帧。
- `scripts/buildings/building.gd` 已维护生产队列、生产时间、建造进度、产金、时代升级进度与完成事件。
- 生产圆环与进度条承担 UI 信息；本方案补充世界内表现。
- 视觉表现只能读取游戏状态，不能改变任何游戏状态；在线模式不发送额外同步数据。

## 设计原则

1. 木石建筑表现为重量和震动，不表现为夸张果冻。
2. 一个状态最多同时触发 2–3 个信号，避免战场过亮、过吵。
3. 生产是循环反馈；升级是持续且累积的反馈；完成是一次明确的奖励反馈。
4. 优先复用现有尘土、出生、爆炸效果；地面环以绘制方式实现，不新增贴图。

## 状态与表现

| 状态 | 现有数据来源 | 世界内表现 | UI |
| --- | --- | --- | --- |
| 闲置 | 队列为空且无升级 | 静止；可选极慢呼吸 | 无 |
| 单位入队 | `queue_unit()` | 一次短促下沉回弹 | 队列图标 |
| 单位生产中 | `production_timer / production_cooldown` | 规律微震，门口/底部尘土 | 生产圆环 |
| 单位完成 | `_spawn_next_unit()` | 一次完成回弹；沿用出生与尘土效果 | 圆环进入下一项 |
| 建筑施工中 | `is_constructed == false` | 半透明、间歇尘土 | 建造进度条 |
| 建筑落成 | `_finish_construction()` | 从略小尺寸弹回原尺寸；2–3 个尘土 | 建造条消失 |
| 资源产出 | `_produce_gold()` | 金色地面脉冲一次 | 金币飘字 |
| 时代升级中 | `set_age_upgrade_progress()` | 城堡持续金色细环，临近完成时加快 | 金色升级条 |
| 时代升级取消 | `set_age_upgrade_progress(0.0)` | 地面环收束，回到闲置 | 升级条隐藏 |
| 时代升级完成 | `_on_age_upgrade_complete()` | 大脉冲与两圈扩散 | 完成飘字 |
| 箭塔开火 | `_spawn_arrow()` | 保留现有轻微回弹 | 无 |
| 受击 | `take_damage()` | 朝攻击反方向偏移 2–3 px 后复位 | 血条 |

## 通用视觉语言

### 建筑本体脉冲

```text
下沉：scale = (1.015, 0.985)，约 0.06 秒
回正：scale = (1.000, 1.000)，约 0.16 秒
```

- 兵营、靶场：可使用默认幅度。
- 城堡、箭塔：最大幅度降到 0.5–1%。
- 箭塔开火沿用 `JellyEffect`，但保持轻微，避免石塔像橡皮。

### 尘土

复用现有 `DustEffectScene`：

```text
兵营生产：1.1 秒一次，底部中央随机横向偏移 8 px
靶场生产：1.5 秒一次，较弱
施工中：0.8 秒一次，底部随机位置
落成：同一时刻 2–3 个尘土，左右展开
```

### 地面环

由组件通过 `Node2D._draw()` 的 `draw_arc()` / `draw_circle()` 绘制。

- 城堡升级：金色细环持续缓慢转动，进度越高越快。
- 产金：金色环快速扩张一次。
- 修道院未来研究：白蓝色细环。
- 兵营、靶场、普通房屋不使用持续地面环。

## 新组件

新增 `scripts/effects/building_activity_visual.gd`，并作为 `ActivityVisual` 子节点挂载到 `scenes/buildings/building.tscn`。

```text
Building
├─ ShadowComponent
├─ HealthComponent
├─ BodySprite
├─ ActivityVisual
├─ HPBar
├─ AggroLine
└─ Garrison
```

组件是纯表现层，拥有一个持续状态与若干短事件。

```text
持续状态：idle / producing / constructing / age_upgrading
短事件：order_received / production_completed / hit / resource_tick
```

优先级：`destroyed > constructing > age_upgrading > producing > idle`。短事件覆盖 0.1–0.4 秒，结束后回到当前持续状态。

### 建议接口

```gdscript
func configure(building_type: int, body: Sprite2D, seed: int) -> void
func set_production(active: bool, ratio: float) -> void
func play_order_received() -> void
func play_production_completed() -> void
func set_construction(active: bool, ratio: float) -> void
func play_construction_completed() -> void
func play_resource_tick() -> void
func set_age_upgrade(active: bool, ratio: float) -> void
func play_age_upgrade_completed() -> void
func play_hit(from_direction: Vector2) -> void
func stop_all() -> void
```

## 接入点

在 `scripts/buildings/building.gd` 中接入，不改动判定逻辑：

| 现有方法 | 调用 |
| --- | --- |
| `_ready()` | 配置 `ActivityVisual` |
| `_production_process()` | `set_production(active, ratio)` |
| `queue_unit()` | 成功后 `play_order_received()` |
| `_spawn_next_unit()` | 完成后 `play_production_completed()` |
| `_produce_gold()` | 产金后 `play_resource_tick()` |
| `start_construction()` | `set_construction(true, 0.0)` |
| 建造倒计时 | 更新施工比例 |
| `_finish_construction()` | `play_construction_completed()` |
| `set_age_upgrade_progress()` | 转发升级状态与比例 |
| `take_damage()` | `play_hit()` |
| `die()` | `stop_all()` |

在线模式中，组件只读取已经由 `TickManager` 驱动的 `production_timer`。随机尘土位置仅为本地表现，不参与同步。

## 默认建筑配置

| 建筑 | 脉冲 | 尘土 | 地面环 | 完成反馈 |
| --- | ---: | ---: | --- | --- |
| 兵营 | 1.5% | 1.1 秒 | 无 | 回弹 + 现有出生效果 |
| 靶场 | 1.0% | 1.5 秒 | 无 | 小回弹 |
| 修道院 | 0.7% | 无 | 白蓝细环 | 轻亮环 |
| 城堡产金 | 0.5% | 无 | 金环闪一次 | 金色脉冲 |
| 城堡升时代 | 1.0% | 完成时有 | 持续金环 | 双环扩散 + 回弹 |
| 农场产金 | 0.8% | 少量 | 金环闪一次 | 保留金币飘字 |
| 箭塔开火 | 轻微 | 无 | 无 | 无 |
| 普通房屋 / 城墙 | 无 | 仅施工 | 无 | 落成尘土 |

目前 FARM 复用 `House1.png`，因此第一阶段不为农场设计独有结构动画。

## 编辑器配置

`ActivityVisual` 根据 `building_type` 自动选择默认配置。仅当某张建筑图的工作点不合适时，才在 Inspector 调整：

```text
activity_anchor：尘土与地面环的相对位置
pulse_strength：0.005 ~ 0.020
pulse_interval：0.5 ~ 1.5 秒
activity_color：金 / 蓝白 / 阵营色
use_dust：是否使用现有 Dust 序列帧
use_ground_ring：是否绘制地面环
```

首先只校准 `barracks.tscn` 的 `activity_anchor`，确保尘土落在门口附近；之后再扩展其他建筑。

## 实施顺序

1. 新增并挂载 `ActivityVisual`，只实现兵营入队、生产中、完成。
2. 接入现有生产队列和生产圆环，不改动生产规则。
3. 在常用 RTS 镜头缩放下调节兵营脉冲、尘土位置和频率。
4. 复用到靶场、城堡产金。
5. 接入时代升级、施工、受击。

## 验收标准

- 兵营入队时，不看 UI 也能察觉它开始工作。
- 生产中不会持续抖到干扰战场阅读。
- 完成反馈明确，但不会遮挡新出生单位。
- 队列清空、升级取消、建筑死亡时，效果立即停止。
- 同屏十几座建筑工作时，不存在每帧创建节点或大量粒子。
- 组件不改变生产计时、资源、单位生成与联机同步。

## 后续扩展

未来异怪建筑可复用同一接口，只需替换视觉配置：将“尘土 + 木石脉冲”改为“肉质回弹 + 紫色脉冲”，无需修改生产系统。
