## 一、为什么要改

### 1.1 当前问题（5 个核心痛点）

| # | 问题 | 影响 |
|---|---|---|
| 1 | **没有农场建筑** | 玩家无法主动扩展经济，只能靠主基地固定产金 |
| 2 | **兵营自动产兵** | 玩家无法决定造什么兵、什么时候造，运营感弱 |
| 3 | **Q+1234 从天而降送兵** | 完全绕过兵营，玩家想在哪造就在哪造，建筑失去意义 |
| 4 | **步兵造价 100 金 + 主基地每次产 30 金硬编码** | 数值无法数据驱动调节，平衡困难 |
| 5 | **没有递增/反还/上限机制** | 没有 PVZ/星际式的"引导分流"机制，玩家无脑暴兵 |

### 1.2 改造目标

让 T1（0-2 分钟）形成清晰的运营节奏：

| 流程 | T1 末状态 |
|---|---|
| **贪农场**（贪经济）| 3 农场完成 + 1 在建 + 0 兵营 + 0 兵（被第一波骚扰惩罚）|
| **稳一手**（经济 + 军事）| 2 农场完成 + 1 在建 + 1 兵营 + 4 兵（轻松防骚扰）|

玩家在 0:30 / 1:00 / 1:30 有 3 个清晰的决策点，自然被引导分流。

### 1.3 核心设计思路

参考 PVZ/星际的"机制性引导"（不是硬限制）：

- **递增加价**：同种建筑每多造一个，造价 += 固定幅度。让玩家"算账"后自然停手
- **完成反还**：建筑完成时反还部分资源。让前期连造可行，后期效率递减
- **兵营主动造兵**：玩家点击兵营 → 选兵种 → 扣金币 → 兵从兵营门口走出
- **农场解锁兵营**：1 农场 = 1 兵营造兵权限（强制先经济后军事）
- **字段化**：所有机制用 stats 字段控制，可灵活调整或关闭（难度调节用）

#### A. 找最近可用兵营

```gdscript
func _find_nearest_available_barracks(unit_type: int, click_pos: Vector2) -> Node2D:
    var candidates: Array = []
    for b in get_tree().get_nodes_in_group("player_buildings"):
        if not b.get("building_type") == D.BuildingType.BARRACKS:
            continue
        if not b.can_produce(unit_type):       # 兵营能造这种兵？
            continue
        if not b.queue_has_space():            # 队列没满？
            continue
        candidates.append(b)
    if candidates.is_empty():
        return null
    candidates.sort_custom(func(a, b):
        return a.position.distance_to(click_pos) < b.position.distance_to(click_pos))
    return candidates[0]
```

##### B. 新增 `refresh_building_buttons_state` 方法

```gdscript
func refresh_building_buttons_state(current_gold: int) -> void:
    for mode in building_modes_ordered:
        var wrapper: Control = ui_buttons.get(mode)
        if wrapper == null: continue
        var cost_label: Label = wrapper.get_node_or_null("CostLabel")
        if cost_label == null: continue

        var stats = _get_building_stats(mode)
        var base_cost: int = D.COSTS.get(mode, 0)
        var actual_cost: int = base_cost
        var state: String = "normal"
        var tooltip_extra: String = ""

        # 1. 递增后实际造价
        if stats and stats.cost_increment > 0:
            var count: int = _count_player_buildings_of_type(mode)
            actual_cost = base_cost + count * stats.cost_increment

        # 2. 上限检查（FARM 最多 5）
        if mode == D.PlaceMode.FARM:
            var farm_count: int = _count_player_buildings_of_type(D.PlaceMode.FARM)
            if farm_count >= 5:
                state = "maxed"
                tooltip_extra = "已达上限"

        # 3. 前置检查（BARRACKS 需要 farm > barracks）
        if mode == D.PlaceMode.BARRACKS:
            var farm_count: int = _count_player_buildings_of_type(D.PlaceMode.FARM)
            var barracks_count: int = _count_player_buildings_of_type(D.PlaceMode.BARRACKS)
            if barracks_count >= farm_count:
                state = "locked"
                tooltip_extra = "需要先造农场（当前 %d 农场 / %d 兵营）" % [farm_count, barracks_count]

        # 4. 金币检查（只在没 locked/maxed 时检查）
        if state == "normal" and current_gold < actual_cost:
            state = "unaffordable"

        # 5. 应用 UI
        match state:
            "normal":
                cost_label.text = str(actual_cost)
                cost_label.add_theme_color_override("font_color", Color.WHITE)
                wrapper.modulate = Color.WHITE
            "unaffordable":
                cost_label.text = str(actual_cost)
                cost_label.add_theme_color_override("font_color", Color.RED)
                wrapper.modulate = Color(1, 1, 1, 0.7)
            "locked", "maxed":
                cost_label.text = "MAX" if state == "maxed" else str(actual_cost)
                cost_label.add_theme_color_override("font_color", Color.GRAY)
                wrapper.modulate = Color(0.5, 0.5, 0.5, 1.0)

        # 6. tooltip 数据（存到 wrapper 的 metadata，hover 时读）
        wrapper.set_meta("tooltip_extra", tooltip_extra)
        wrapper.set_meta("actual_cost", actual_cost)
        wrapper.set_meta("state", state)
```

### 8.7 兵营队列实现细节

#### 数据结构

```gdscript
# building.gd (BARRACKS 实例)
var production_queue: Array[StringName] = []   # 排队的单位 id
const QUEUE_MAX: int = 5                       # 单兵营队列上限

func queue_has_space() -> bool:
    return production_queue.size() < QUEUE_MAX

func queue_unit(unit_id: StringName) -> void:
    production_queue.append(unit_id)

func _production_process(delta: float):
    if production_queue.is_empty():
        return
    production_timer += delta
    if production_timer >= production_cooldown:
        var unit_id: StringName = production_queue.pop_front()
        _spawn_unit_at_door(unit_id)
        production_timer = 0.0
```

```gdscript
func _spawn_unit_at_door(unit_id: StringName):

    spawner_module.spawn_unit_near(unit_id, door_pos, Team.PLAYER)
```

```gdscript
# 进度更新时（每帧或每 0.1s）
```

## 九、骚扰波次设计（T1 + 中后期）

### 9.1 设计原则

1. **骚扰来源**：从**敌方最终基地刷出**（不是 SH1 据点派出，避免与据点指挥官系统冲突）
2. **SH1 定位**：玩家攻下来后作为"分矿"/前进基地，**不是骚扰源**
3. **目标逻辑**：最终目标玩家主基地；**路过单位优先打单位**，否则打建筑；不打玩家主基地路上绕路
4. **提示**：每波前 **30 秒警告**（如 1:30 提示"30 秒后敌人来袭"），2 分钟整刷出 + 开始走，**实际接敌更晚**（路径消耗约 18 秒）
5. **频率**：每 2 分钟一波
6. **战力单调递增**：强度只能涨不能降，**只有递增速度（斜率）变化**

## 十、SH1 据点设计（占领 + 选择 + 科技建筑）

### 10.1 设计目标

把 SH1 从"纯战斗目标"升级为"战略决策点"：
- 玩家 4-5 分钟推完 SH1 → 获得**长期战略收益**
- 收益依赖**特殊科技建筑**（玩家自选 1 个）→ 形成 build 差异化
- 特殊建筑是**脆弱的高价值目标** → 逼迫玩家防守据点
- 全程**无弹窗、无暂停**，所有反馈在场景内

### 10.2 占领机制（场景化反馈）

**触发条件**（双条件 AND）：
1. 据点范围内所有**原属敌方的建筑**全部被消灭
2. 据点范围内**没有原据点守军单位**（玩家单位可以存在）

**反馈方式**：
- 触发瞬间，据点中心**出现光圈**（地面发光特效，类似建造预览的绿圈但更醒目）
- 光圈本身就是"可建造区"标识，半径 6 格
- 玩家在光圈内建造任意 1 个特殊建筑 → 视为正式"占领"
- ❌ **不暂停、不弹窗**——所有反馈在场景内

### 10.3 新基础设施:建造范围限制系统

这是据点机制 + 候选 A 的共同依赖。

**当前问题**：建筑可建在地图任何位置，无范围限制。

**改造方案**：
- 每个己方建筑周围有 **6 格半径建造影响圈**
- 主基地的影响圈是初始可建区
- 据点光圈是额外的可建区
- 玩家在影响圈外尝试建造 → 预览变红、无法放置
- 影响圈可视化（建造模式下显示，类似 PVZ 种植区）

**未来扩展**：
- 敌方主基地周围可设"禁建区"
- SH2/SH3 据点继承同一机制
- 地图机制区（桥、隘口）可特殊化

### 10.4 据点建筑栏 UI（核心交互）

**显示规则**：
- 默认隐藏
- 占领据点后**自动出现**新建造栏分类（建造栏顶部多一个"据点"按钮）
- 点击"据点"分类 → 显示 4 个候选建筑卡片

**UI 设计要点**：
- ⭐ **效果描述必须显眼**（玩家做决策的核心信息）
- 每个卡片包含：
  - 建筑名称（大字号）
  - 图标 + scale 1.3 缩略图
  - 效果描述（2-3 行，关键数值标红或加粗）
  - 造价
  - "建造此建筑"按钮（或点卡片即进入建造模式）

**操作流程**：
1. 占领据点 → 建造栏顶部出现"据点"分类按钮（带新提示标志）
2. 点"据点" → 显示 4 个候选
3. 选 1 个 → 进入建造模式（Q+W 已切换）
4. 鼠标移到光圈内 → 预览变绿
5. 左键放置 → 扣金币、开始建造
6. 建造完成 → 其他 3 个候选**永久移除**（该据点锁定）

### 10.5 四个候选建筑

#### A. 丰收祭坛（经济型）

- **类型**：高产能经济建筑（类似小型主基地）
- **效果**：本身每 10s 产 60 金（= 3 个农场的产能）
- **造价**：400 金（长期投资，约 67s 回本）
- **HP**：300（高于普通建筑）
- **占用**：据点光圈内 1 格
- **战略价值**：把据点变成"第二经济中心"，支撑 T2/T3 暴兵
- **风险**：被打掉 = 经济崩盘风险
- **状态**：本阶段先文档化，与"建造范围限制系统"一起做

#### B. 时代圣殿（科技型）

- **效果（主方案）**：所有科技升级 **-30% 消耗 + -30% 时间**
- **效果（备选方案）**：T2 升级成本 -40%
- **造价**：300 金
- **HP**：200
- **战略价值**：加速冲 T2/T3，获得兵种优势
- **风险**：体感无聊（看不到画面变化），需要加视觉表现（圣殿发光、单位路过加 buff 特效）
- **状态**：本阶段先文档化，T2 阶段再实装

#### C. 高级弓箭手祭坛（战斗型）⭐ 阶段 1 起步

- **效果**：建造完成时**生成 1 个高级弓箭手**
- **单位设计**：
  - 复用弓箭手模型，scale 1.3x
  - HP 150 / ATK 18 / 攻击范围 60（高于普通弓箭手）
  - **分裂攻击**（一次射出 3 支箭，同时打 3 个不同目标）
- **造价**：350 金
- **HP**：200
- **战略价值**：弥补 T1 全近战的火力空缺，作为部队核心
- **扩展性**：分裂攻击机制可复用于其他精英、指挥官、防御塔
- **科技持续性**：祭坛被打掉 → 已产出的高级弓箭手**保留**

#### D. 战备兵营（升级型）

- **效果**：
  - 玩家在据点光圈内建造兵营 → **返还该兵营全部造价**（免费兵营）
  - 该兵营产出的所有单位**永久 +1 升级等级**（突破 max_upgrade_level）
- **造价**：等同普通兵营 300 金（建造时立即返还）
- **HP**：200（同普通兵营）
- **战略价值**：精锐部队产地，每兵 +10 HP / +2 DMG
- **依赖**：兵营需要**部队标识** tag（新机制，标记从该兵营出的单位归属）
- **科技持续性**：兵营被打掉 → 新兵不再有 +1 加成；已存活兵保留属性（避免"属性突然下降"糟糕体感）
- **状态**：本阶段先文档化，等"部队标识"基础设施做完再实装

### 10.6 科技持续性规则（一致性表）

| 候选 | 建筑被打掉后 | 已产出单位 | 已施加的科技/buff |
|---|---|---|---|
| **A 丰收祭坛** | 产能消失 | — | — |
| **B 时代圣殿** | 未来不再享受折扣 | — | 已升级的 T2 不倒退 |
| **C 高级弓箭手祭坛** | 不再产出新单位 | **保留**（单位本体不消失）| — |
| **D 战备兵营** | 新兵不再有 +1 加成 | **保留**（已存活兵属性不倒退）| 该部队的 +1 加成对**新兵**失效 |

**一致性原则**：
- ✅ 已产出的**单位本体**保留（不消失）
- ✅ 已施加在单位上的**属性**保留（不倒退）
- ❌ 建筑提供的**未来增益**消失（新兵不再加成 / 新科技不再折扣 / 新产能不再产出）

### 10.7 据点归属判定

**核心规则**：
- 据点范围内**有任何己方建筑** = 玩家占有
- 据点范围内**没有任何己方建筑** = 据点废弃（光圈永久消失，特殊建筑槽位消耗）

**特殊性**：
- ❌ **不回归中立**：据点一旦被玩家占领过，永久属于玩家或废弃
- ❌ **敌方无法占领**：敌方只能破坏，不能"夺回"据点
- ❌ **光圈一次性**：每个据点的特殊建筑槽位只能用 1 次（被打掉不重置）

### 10.10 关键设计决策

| # | 决策 | 理由 |

| 1 | 占领触发用"清空守军 + 清空建筑"双条件 | 防止"拆完建筑就跑"的取巧玩法 |

| 6 | 据点不回归中立、敌方无法占领 | 简化归属逻辑，避免拉锯战 |
| 7 | 建造范围半径 6 格 | 给玩家足够空间，但不无限扩展 |

| 10 | 候选 A 改为单座高产能建筑 | 简化"3 农场连锁消失"逻辑，工程量小 |
