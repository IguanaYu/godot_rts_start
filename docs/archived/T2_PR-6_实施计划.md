## 四、实施步骤

### 步骤 1：T2 三流程推演（1.5h）

#### 流程 A：防守流推演
1. 进入 T1 测试地图（map_t1_economy_test）
2. 0:00-3:00：贪农场 + 升 T2（500 金 + 15s）
3. 3:15-3:30：升完后反还 300 金，建靶场（250 金）
4. 3:35-3:55：靶场建造完成，造 1 个弓兵（100 金）
5. 4:00-5:00：再升 1 级通用 HP（300 金）+ 农场科技（500 金）
6. 5:30 第 3 波骚扰：玩家应有 1-2 弓兵 + 4-5 步兵 + 1 级通用 HP
7. 6:00-7:00：守完第 3 波，继续补兵 / 升级
8. 7:30 第 4 波骚扰：玩家应有 8-12 兵（含 1-2 弓兵）+ 0-1 级全局升级

**预期状态对比**：
- [ ] 4:00 状态：3 农场 + 1 兵营 + 1 靶场 + 1 弓兵 + ~50 金
- [ ] 6:00 状态：3 农场 + 1 兵营 + 1 靶场 + 5 步兵 + 1 弓兵 + 1 级通用 HP
- [ ] 8:00 状态：3 农场 + 1 兵营 + 1 靶场 + 8 步兵 + 2 弓兵 + 1 级通用 HP

#### 流程 B：暴兵流推演
1. 0:00-2:00：建 2 农场 + 2 兵营 + 反 4 soldier
2. 2:00-4:00：狂造兵（双兵营 15s/兵，4 分钟约 12 兵）
3. 4:00-4:30：升 T2（500 金）
4. 4:30-5:30：攒兵推 SH1 据点
5. 5:30 第 3 波骚扰：玩家有 12+ 兵应对

**预期状态对比**：
- [ ] 4:30 状态：2 农场 + 2 兵营 + 0 靶场 + 12 兵 + ~100 金
- [ ] 6:00 状态：2 农场 + 2 兵营 + 推 SH1 中 + ~6 兵

#### 流程 C：平衡流推演
1. 0:00-3:30：贪农场 + 单兵营稳造兵
2. 3:30-4:00：升 T2
3. 4:00-5:00：建靶场 + 造弓兵 + 升 1 级通用 HP
4. 5:30 第 3 波骚扰：玩家有 6 兵 + 1 弓兵应对

### 步骤 2：20 关回归测试（1h）

#### 关键关卡冒烟测试
1. M1（早期关）：进入 → 造几个农场/兵营 → 攻击敌方 → 验证基础流程
2. M5（技能教学）：进入 → 用技能 → 验证不报错
3. M12（推进关）：进入 → 推进 → 验证不报错
4. M20（最终关）：进入 → 验证可玩

#### WALL→FARM 改造影响检查
1. grep "type.*=.*0" 检查所有 map_config 里 WALL 引用
2. 确认每关 WALL 配置在 FARM 改造后仍合理（如某关 WALL 是"路障"语义，可能要换成 TOWER 或重设）
3. 修复发现的报错或语义错误

#### initial_gold 异常值修正
1. grep "initial_gold" 找所有 map_config 的开局金币
2. 异常值（如 M12=5000）调整为合理值（建议 400-600）
3. 注意：T1 阶段已统一为 400（NORMAL），但旧关可能没改

### 步骤 3：骚扰节奏验证（30min）

1. 跑流程 A 防守流，关注第 3-4 波骚扰时机：
   - 第 3 波（5:30 警告 / 6:00 出兵）：玩家应有 1-2 弓兵
   - 第 4 波（7:30 警告 / 8:00 出兵）：玩家应有 2-3 弓兵 + 8 步兵
2. 验证骚扰方弓兵 + 玩家弓兵的远程对射节奏合理（不是一边倒）
3. 如果骚扰方太强 / 太弱，调整第 3-4 波的弓兵数量

### 步骤 4：数值微调（30min）

根据推演结果调整（如需要）：
- T2 升级反还 300 金不够用？→ 调到 400 或 500

- 兵营递增 300/350/400 太贵？→ 调到 250/300/350
- 升级节点费用不平衡？→ 调整对应 .tres

### 步骤 5：科技点系统决策（30min）

用户决策"先不理他，可能没有了"。本 PR 收尾时确认：

## 六、风险与注意事项

### 6.1 高风险
- **20 关回归暴露大量 bug**：T1 期间冻结的债，可能在回归时集中爆发。建议留 4-6h 缓冲时间
- **数值微调引发新不平衡**：改了 T2 反还金额可能影响流程 A/B/C 都不达标。每改一项数值后**重新跑一遍三流程推演**

### 6.2 中风险
- **流程推演人为误差**：人手操作不可能精确，状态对比要给容差（如 ±50 金 / ±15s / ±2 兵）
- **科技点系统移除工作量**：完整移除涉及多个文件（tech_point_data / tech_point_manager / main.gd / game_ui.gd 等），预估 1-2h。建议选项 B（保留代码）

### 6.3 注意事项
- **不要在 PR-T2-6 加新功能**：本 PR 只做验证 + 微调。新功能发现的问题记录到 T3 阶段待办
- **T2 阶段验收报告很重要**：T3 阶段接手时第一份要看的文档。要把 T2 的实际状态、已知 bug、待优化项都写清楚
- **20 关回归测试可以分散到 PR-T2-3/4/5**：如果时间紧，每个 PR 完成后跑一遍 4-5 关冒烟，PR-T2-6 集中跑剩下的
