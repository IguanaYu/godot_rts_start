## 四、关键技术决策（全部已和用户确认）

### 4.1 时代挪动（PR-1）

- 僧侣（MONK_UNIT）+ 修道院（MONASTERY）从 T1 挪到 T2 解锁
- 长矛兵（LANCER）从 T1 挪到 T3 解锁
- **长矛兵不新建独立兵营**，沿用 BARRACKS，T3 后兵营多一条长矛兵生产线
- map_config.available_items（战前编制）**不动**；时代过滤在 unlocked_items 层做。编制里有但时代没解锁的，进游戏造不了

### 4.2 T3 升级架构（PR-2）

- **标签系统**：UnitStats 加 `unit_tags: Array[StringName]` 字段。本期做 `boss` / `heavy_armor` / `light_armor` 三种
  - 步兵挂 `heavy_armor`
  - 弓兵 / 僧侣挂 `light_armor`
  - BOSS 级近战挂 `boss`（如果将来加）
  - 长矛兵 T3 升级 = "对 boss 标签单位 +50% DMG"（复用现有 `bonus_vs_unit_types` 机制扩展）
- **N 选 1 升级实现方式**：场景替换（旧单位 free + 新单位生成）
  - 每个变体单位是独立的 .tscn（基于现有 unit.tscn 复制修改）+ 独立的 stats.tres
  - 共享 unit.gd 脚本（不写子类）
  - 变体通过 stats_id 区分（如 `berserker` / `shield_guard`）
- **生效时机**：玩家在弹窗确认后，**延时 0.5s + 全兵种闪光特效**，然后场上所有该兵种单位场景替换
- **HP 处理**：按比例继承（旧单位 70% HP → 新单位 70% max_hp）
- **T1/T2 已购升级**：全继承（新单位场景替换后，把已购升级的 modifier 重新 apply 到新 stat_set）
- **状态继承**：位置 / 移动目标 / 攻击目标 / 控制组归属 / alliance_id 全部继承

### 4.3 据点定义（PR-3）

- 据点 = **敌方城堡**（BuildingType.CASTLE + team != 0）
- 胜利条件复用 `victory_destroy_base.gd`（已经支持"摧毁敌方 CASTLE = 胜利"）
- 失败条件沿用现状（玩家城堡被毁 = 失败）

### 4.4 胜利统计画面（PR-3）

- **追踪 7 项**：用时 / 剩余金币 / 获得金币总数 / 击杀数 / 死亡数 / 建造单位数 / 建造建筑数
- 不做"每单位伤害总量"（改动面太大，留到后期）

### 4.5 T3 学院交互（PR-2）

- 选中 T3 学院 → 详情面板显示 4 条研究项按钮（步 / 弓 / 僧 / 长矛）
- 点击某项 → 屏幕中央弹窗显示 N 选 1 候选
- 弹窗内"确认"按钮 → 触发场景替换
- 研究费 1000 金 / 项，研究时间 = 即时生效（延时只是动画，不阻塞玩家）

### 4.6 开局一次性提示（PR-3）

- 进游戏时弹一次性居中提示（"摧毁敌方据点获胜"）
- objectives_panel.gd（右上角 Info 面板）的 Objectives 区**常驻**显示本局任务
- 不依赖 SaveManager，每次进游戏都显示一次提示，但提示有"知道了"按钮可关闭

### 4.7 塔数值（PR-4）

- 决策稿 A 已定方向，本阶段直接定初始数值：
  - 递增造价：第 N 座 = 180 + (N-1) × 50 金
  - 攻击范围：150 → 220
  - HP：150 → 180
  - DMG：12 → 14（DPS 9.3 → 10.8）
  - 攻速：保持 1.5s

## 六、风险与已知问题

1. **PR-2 复杂度最高**：场景替换 + 标签系统 + 弹窗 UI + 10 个变体 stats.tres，弱模型容易写出 bug。PR-2 文档会拆成多个子任务（PR-2a 标签系统 → PR-2b 变体资源 → PR-2c 学院建筑 → PR-2d 弹窗 UI → PR-2e 场景替换），按顺序执行。
2. **数据追踪埋点多**：PR-3 要在 unit.gd 死亡、building_placer 放置、game_spawner 产兵、main.add_gold() 4 处埋点，漏一个就数据不准。文档会列全所有埋点位置。
3. **现有变体单位（ALTAR_ARCHER 等）的影响**：标签系统新加字段时不要破坏现有 category 字段，PR-2 会明确。
4. **map_config 优先级**：当前 `_apply_loadout_filter`（[main.gd:1695-1705](../../scripts/main.gd#L1695)）覆盖 available_items。时代挪动只动 unlocked_items，不动 available_items。
