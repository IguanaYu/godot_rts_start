# 游戏 UI 设计定式 — 跨游戏与设计系统调研

> 数据源: 智谱多引擎搜索（search_pro + 搜狗）40+ 关键词 / 知乎 / 优设 / Material Design / Apple HIG / Bootstrap / Tailwind / Ant Design / WCAG / 游戏社区
> 采集日期: 2026-08-08
> 用途: 回答"游戏 UI 有没有设计定式（固定比例/尺寸/字号/行数）"，为本项目 RTS 的 HUD 布局、底部栏、文字图标、间距提供决策支撑
> 调研重点: ① 左上角资源显示有无固定比例 ② 底部菜单占屏比 ③ 文字/图标/行数有无计算比例 ④ 非游戏 UI 的可借鉴定式
> 原始资料: 50 份搜索 JSON 原样存档于 `ui_design_patterns_materials/`（见文末清单）

## 0. 一句话总结

**UI 设计"定式"分两类，结论先说：**

1. **硬定式（有固定数值，可直接套用）**：间距/尺寸走 **8pt 网格**、行高≈字号×**1.5**、字号用**模块化比例**（×1.25/1.333/1.618）、图标走 **8 的倍数**（16/24/32/48/64）、点击目标 **≥48dp/44pt**、文字对比度 **≥4.5:1**、间距阶梯 **4/8/16/24/48**（多个系统交叉验证）。这些是从 Material/iOS/Web 设计系统里**提炼出的、跨平台反复验证的**定式。
2. **经验法则（有比例但非精确）**：黄金比例 Φ≈1.618、三分法、底部菜单占屏高、屏占比区间。这些是"参考值"，不是"标准答案"。

**关于"左上角金钱大小比率 / 底部菜单占多少比例"**：RTS 公开资料里**几乎搜不到权威像素数据**（这是本次调研的重要发现，见 §5）。但通过旁证可以得到一个可信区间：**WC3 在 1024×768 下，底部命令栏 + 顶部资源面板合计约 198px 高（≈26% 屏高），场景渲染区只剩 1024×570**。非游戏 UI 的底部工具栏定式是 **40~48px**（桌面 1080p 下约 4-5%）。本项目底部栏 220px/720px ≈ **30.6%**，偏高（详见 §5 待决策点）。

**核心建议**：本项目应把"8pt 网格 + 模块化字号 + 间距阶梯 + 点击目标 + 对比度"作为**计算基础**（这些是真正能算出"图标=字号×1.5"这类比例的体系），把"底部栏占 ~26-30%、资源栏角落布局"作为**布局参考**。

## 1. 案例事实（先穷举）

### 1.1 RTS 游戏 HUD 布局

| 游戏 | 资源栏位置 | 命令栏位置 | 关键数值 | 来源 |
|------|-----------|-----------|---------|------|
| 星际争霸2 (SC2) | 右上角（横向 3 组） | 底部右下方块 | 界面与星际1同源（地图/单位/资源/聊天分区）；支持 16:9 / 16:10 / 4:3 | 新浪科技 2008、PConline 2010（搜狗） |
| 魔兽争霸3 (WC3) | 右上角（纵向 3 行） | 底部全宽命令栏 | **1024×768 下场景渲染区仅 1024×570，UI 占高 198px ≈ 26%** | 博客园 winsonchen（搜狗） |
| 帝国时代2 (AoE2) | 左上角（横向 4-5 组） | 左下按钮区 | 顶部资源栏图集 UITopBarAtlas 512×256；标准分辨率 1280×1024 | 爱给网、ZOL（搜狗） |
| 命令与征服/红警 (C&C) | 屏幕右侧边栏 | 右侧竖栏 | 侧边栏式布局（区别于暴雪派底部式） | 百科（搜狗，弱） |

**RTS 布局的两大范式**：
- **暴雪派（SC2/WC3）**：资源在**右上角**、命令在**底部**，用屏幕**上下两条"带"**，中间留给战场。
- **Ensemble 派（AoE）**：资源在**左上角**、命令在**左下**，偏重左对齐。
- **Westwood 派（C&C）**：整个指挥界面做成**右侧侧边栏**（竖条），左侧全战场。

> 结论：RTS 资源栏"角落 + 常驻 + 不挡视野"是通用定式；具体左右角取决于流派，不是强约束。

### 1.2 WC3 底部栏的具体尺寸（本次找到的最硬 RTS 数据）

- **场景渲染区 1024×570**（在 1024×768 分辨率下）→ 底部命令栏 + 顶部资源面板合计占屏高 **26%**。
- **UI 占屏约 1/4**：原文明确"能够避免四分之一的 ui 窗口区域无效渲染"，即 RTS 顶部+底部 UI 合计约占 1/4 屏幕高度。
- WC3 自定义 UI（FDF 系统）控件的宽高、坐标、对齐方式均可精确到像素定义（CSDN CarlosX 教程）。
- 原版 WC3 UI 不支持宽屏，高分辨率下 UI 元素重叠（试错教训，见 §3）。

### 1.3 布局比例 / 网格系统

**8pt 网格（硬定式）**：
- 所有间距/内边距/元素尺寸用 **8 的倍数**（8/16/24/32/40/48/56…），需要更细时用 **4px**。
- Material Design 是 **4pt 栅格**；iOS 偏"软栅格"（只检查间距是否 8 倍数）。
- **行高 ≈ 字号 × 1.5** → 16/24、21/32、24/36、32/48；文字走 **4pt 基线网格**（行高为 4 倍数）。
- 图标固定 8 倍数：16×16、24×24、32×32、64×64。
- 设计统一在 1x 画板，导出 @2x/@3x；rem 基准 16px 用 0.5rem 步进。
- 来源：知乎 8pt 译文、优设 8-pt 网格系统、设计达人

**Android Material 具体值**：最小可点击 **48×48dp**；状态栏 24dp、AppBar 56dp、底部导航 48dp、FAB 56×56（mini 40）、卡片间距 8dp、屏幕左右留白 **16dp**、文字左对齐基线 **72dp**、可变控件宽度按 56dp 倍数。（CSDN Android 规范）

**12 列栅格**：桌面 12 / 平板 8 / 移动 4；通用列宽 60-80px；gutter 常用 **20px**；移动端侧边距 20-30px。Bootstrap：12 列、gutter **24px(1.5rem)**。960px 网格因可被 3/4/5/6/8/10/12/15/16 整除成为经典基准。（SitePoint / Elementor / MDB）

**黄金比例 Φ≈1.618**：正文 14px → 标题 14×1.618≈22.7px；960px 布局 → 内容 960/1.62≈**593px**、侧栏 **367px**。三分法=黄金比例简化版（1:1:1，交点放重点元素）。（Cubet / CorelDRAW）

**安全区 / 分辨率适配**：
- 设计基准 **16:9**，常用 **1280×720 / 1334×750 / 1920×1080**；1080p 是 PC 端基准（Steam 占比 52.83%），720p 足够像素风。
- 缩放规则：**>16:9（全面屏 19.5:9）→ 短边为适配基准**；**<16:9（iPad）→ 长边为适配基准**；UI 比例不变。
- 贴边 UI 延展尺寸：左右 1624×750、上下 1334×1000、四向 **1624×1000**；背景图统一 1334×750。（知乎手游适配）

### 1.4 文字 / 图标 / 间距系统（各设计系统字号阶梯）

**Material Design M3 字号阶梯**（硬定式）：

| Type role | 字号 | 行高 |
|-----------|------|------|
| Display | 57 / 45 / 36 | 64 / 52 / 44 |
| Headline | 32 / 28 / 24 | 40 / 36 / 32 |
| Title | 22 / 16 / 14 | 28 / 24 / 20 |
| Body | 16 / 14 / 12 | 24 / 20 / 16 |
| Label | 14 / 12 / 11 | 20 / 16 / 16 |

**模块化字体比例（modular scale，计算定式）**：
- 公式：`value = 基准 × ratio^n`
- 常用比值：**1.25（major third）/ 1.333（perfect fourth）/ 1.5（perfect fifth）/ 1.414（aug. fourth）/ 1.618（golden）**
- 例：16px 基准 ×1.333 → 12/16/21/28px；16px 基准 ×1.618 → 16/26/42px
- 这就是"字号有固定计算比例"的**权威答案**——它是网页/App 设计里最常用的字号生成公式。

**行高 / 行宽**：正文 1.5×字号、标题 1.2×、段落间距 1.25×；行宽推荐 45-75 字符（Web 常识，本次未直接命中权威源，标为经验值）。

**图标尺寸**：Material 8/12/16/24/32/48/56/64dp；**常用 24dp 图标**；Avatar 40dp；iOS App 图标 48dp（@2x 96px）。Android 启动图标：MDPI 48×48、HDPI 72、xhdpi 96、xxhdpi 144（CSDN）。

**点击目标（硬定式）**：Material ≥**48×48dp**（图标间距≥8dp）、按钮高 36dp；Apple **44pt**（@2x 88×88px）；Web 按钮 ≥44×44px。（Fitts's Law 底层支持——目标越大越好点，本次 type_35 搜索为噪声，数值来自 Material/HIG）

**中文游戏 UI 字号（@2x px→pt，CSDN/知乎）**：导航 34px(17pt) / 标题 30(15) / 副题 28(14) / 正文 26(13) / 辅助 24(12) / 底部提示 22(11)。这是**移动游戏**常用阶梯，非 RTS PC 端。

**文字 vs 图标比例**：**无固定数学比例**，仅经验"图标 ≈ 字号 × 1.5~2"（正文 16px 配 24-32px 图标）；两者都落在 8dp 网格上以对齐。M3 中图标尺寸由**触控目标(48dp)决定而非字号**。

### 1.5 非游戏 UI 设计系统（网页 / 桌面 / 移动）

**Design Tokens（设计令牌）**：Salesforce 2014 提出。三层命名：**全局 token**（$red-1、$size-3，抽象原始值）→ **语义 token**（$color-text-primary、$spacing-md）→ **组件 token**（$size-image-s:$size-3）。语义层只改一处全局联动，支持明暗双主题、多品牌换肤。**间距建议用"基础间距 × n"表达而非散值**。（tr.designtokens.org / 知乎）

**间距系统（多系统交叉验证，硬定式）**：
- **Bootstrap** $spacer = 1rem = 16px，0.25rem=4px 步进：spacer-1=4 / -2=8 / -3=16 / -4=24 / -5=48
- **Tailwind** spacing：8/16/24/32/40/48/64，统一 4px 基数
- **Ant Design**：基础间距 8px，**小8/中16/大24**，纵向间距公式 **y=8+8n**；用 24 栅格
- **Material**：8dp 栅格最小单位，留白 16dp，卡片间距 8dp

**内容宽度 / 侧栏比例**：容器 max-width：Bootstrap 断点 540/720/960/1140/1320px；主流内容区 960/1200px（面向所有人取 960，年轻向取 1200）；安全边距 24~32px。**侧栏比例 25%/75%**（col-3/col-9）。

**桌面工具栏/菜单栏高度**：导航栏/工具栏 **40~60px**（常见 40px、50dp、56dp）；Material top appbar 小 56dp、大 64dp。

**Dashboard 信息密度（对游戏 HUD 有直接参考）**：首屏 **≤5-6 张卡片**，尽量一屏不滚动；重要信息放**左上角**；字体 **1 款字体、≤3 字重、≤4 种字号**；数字避免多余小数。（知乎 Dashboard / PowerBI / Yellowfin）

**WCAG 对比度（硬定式）**：对比度公式 (L1+0.05)/(L2+0.05)；**普通文本 AA ≥4.5:1、AAA ≥7:1；大文本 AA ≥3:1；UI 组件/图形 ≥3:1**。（W3C）

## 2. 归纳分类：定式 vs 经验法则

### 2.1 可直接套用的硬定式（有固定数值 + 多源交叉验证）

| # | 定式 | 数值 | 适用本项目 |
|---|------|------|-----------|
| 1 | 间距/尺寸网格 | 8 倍数（8/16/24/32/40/48/56），细分 4px | 底部栏内部间距、面板 padding |
| 2 | 行高 | ≈ 字号 × 1.5（文字走 4pt 基线） | 所有 Label/文本 |
| 3 | 模块化字号 | 基准 × 1.25 / 1.333 / 1.618 | 标题/正文/辅助的字号阶梯 |
| 4 | 图标尺寸 | 8 倍数：16/24/32/48/64；常用 24 | 资源图标、单位图标 |
| 5 | 点击目标 | ≥ 48dp（Apple 44pt） | 按钮、单位命令格 |
| 6 | 对比度 | 正文 ≥4.5:1、图形 ≥3:1 | HUD 可读性下限 |
| 7 | 间距阶梯 | 4/8/16/24/48；Ant: y=8+8n | 纵向层级（面板内） |
| 8 | 侧栏/主内容 | 25%/75% | 详情面板 vs 战场 |
| 9 | 工具栏高度 | 40-48px（桌面 1080p ≈4-5%屏高） | 底部命令栏参考下限 |
| 10 | 信息密度 | 首屏 ≤5-6 卡片；1 字体 ≤3 字重 ≤4 字号 | 底部栏分区数、字号种类上限 |

### 2.2 经验法则（有比例、非精确）

| # | 法则 | 数值/规则 | 说明 |
|---|------|----------|------|
| 1 | 底部菜单占屏 | RTS 顶部+底部合计 ≈ **26% 屏高**（WC3 实测）；桌面底部工具栏 4-5% | 游戏底部栏通常 20-30% 合理 |
| 2 | 黄金比例 | Φ≈1.618：内容 960→593+367 | 布局分栏参考，非强制 |

| 5 | 图标:文字 | 图标 ≈ 字号 × 1.5~2 | 经验值，非公式 |

## 3. 试错教训（社区与设计师踩过的坑）

1. **RTS 高分辨率下 UI 重叠（WC3 原版）**
   - 原版 WC3 UI 不支持宽屏，高分辨率下 UI 元素互相重叠，玩家只能靠"按 F7 刷新窗口"临时规避（WarcraftHelper CSDN）。
   - **教训**：UI 布局必须**分辨率无关**（本项目 stretch=canvas_items+expand 已规避），且 UI 元素位置不能写死像素。

2. **奇数像素出毛边（中文 UI 通用）**
   - 中文 UI 字号/间距不用奇数，12/14/16/18 用偶数，奇数像素出毛边。（CSDN/知乎）
   - **教训**：本项目 Label 字号、图标尺寸建议走偶数 + 8 倍数。

3. **间距种类过多反而混乱**
   - 间距定值种类不宜过多，**约 6 个即可覆盖大多数场景**（Ant Design 实践）。
   - **教训**：底部栏别每个面板用不同 padding，统一 8/16/24。

4. **只用颜色/透明度表达层级失败**
   - Material 警告"只用颜色或透明度无法表达层级"，需靠阴影/elevation。
   - **教训**：RTS 单位/建筑选中态、按钮层级不能单靠颜色，要加描边/阴影/背景。

5. **Dashboard 十大戒律**：过度用色、信息过密致认知过载、关系混淆、数据造假均踩坑；首屏塞超过 6 张卡片玩家读不过来。
   - **教训**：底部栏分 3 段（快捷队列/详情/小地图）已是合理上限，别再堆第 4 段常驻。

6. **过度留白稀释信息密度**（Ant 文档明言）：槽(gutter)越大页面越松散。
   - **教训**：RTS 底部栏不能太空，220px 高度里要能一眼抓到资源/队列/详情。

7. **资源面板横向超过 5 项读不过来**（承接《资源面板UI_跨游戏调研》）
   - SC2 社区 compact UI 概念帖证明：超过 5 项横向排列，玩家瞄一眼无法识别。
   - **教训**：左上/右上资源项 ≤5 个，重要项大字 + 次要项小字。

## 4. 新增方向（用户没问但相关）

1. **游戏专用安全区（notch/Home 条）**：本次 safe_area 搜索全为噪声，但手游/主机 UI 必须处理刘海与 Home 条（内容居中对称内缩、可点控件放安全区下方、Home 条周围留足空间）。本项目是 PC 端 RTS，**暂时可豁免**，但未来出移动端/主机要考虑。

2. **21:9 / 超宽屏适配**：WC3 重制版被玩家要求 21:9（2560×1080 注册表改 reswidth）。本项目 stretch=canvas_items+expand 已自动左右延展，但要检查贴边 UI（资源栏、命令栏）在超宽屏下是否被拉变形——**建议固定 UI 尺寸、只延展战场**。

3. **Design Tokens 化**：本项目 UI 有多处硬编码颜色/字号（按钮 factory、底部栏），可引入"全局 token → 语义 token"两层，支持未来换肤/明暗主题。这是本次调研里**架构层面最值得借鉴的非游戏 UI 实践**。

4. **信息密度分级**（承接《资源面板UI_跨游戏调研》§4.4）：按更新频率分级——高频（金币/人口）大字显眼、低频（击杀/波次）小字可折叠。与 Dashboard"首屏≤5-6卡片、≤4字号"定式完全吻合。

5. **底部栏占比的量化工具**：WC3 的 1024×570 说明 RTS 场景渲染区高度是可测量的。本项目可用同样方法：**在 1280×720 视口下，把底部栏和战场分界用网格叠加图校准到 8pt 网格 + 26-30% 区间**。

## 5. 待决策思考点（不替用户拍板）

1. **底部栏高度 220px/720px ≈ 30.6% 是否合适？**
   - 旁证：WC3 全 UI 占高 26%（含顶部+底部）；桌面工具栏定式 4-5%。本项目底部栏 30.6% 比 WC3 总 UI 还高。
   - 参考：若缩到 ~26%（≈190px），或保持 30% 但把顶部资源栏做薄。**30% 对 RTS 是否偏大，取决于战场 FOV 是否还够**——请实测。

2. **底部栏横向三段比例（30% / 40% / 20%）是否与"25/75 侧栏"定式一致？**
   - 当前：快捷队列 30% / 详情 40% / 小地图 20%（剩余 10% 弹性）。
   - 非游戏 UI 侧栏定式是 25%/75%；游戏无直接对应，但详情 40% 是否过大值得权衡。

3. **字号阶梯选哪套基准？**
   - 本项目 viewport 1280×720（16:9 基准）。若用 M3 阶梯 @720p：正文 14-16px、标题 22-28px、辅助 12px 较合理；若按"模块化 ×1.333"从 14px 起：14/19/25/33。
   - 需要确认：像素风美术是否允许更小字号（720p 下 12px 够不够读）。

4. **8pt vs 4pt 网格？** Material 用 4pt、Bootstrap/Tailwind 用 4px 基数、游戏图标用 8 倍数。本项目 viewport 720p 下，**4px 粒度**可能更实用（8px 在 720p 上偏大）。

5. **是否引入 Design Tokens？** 现在 UI 颜色/字号多处硬编码，迁移成本 vs 收益（换肤/明暗主题/一致性）需要权衡。建议至少把"间距阶梯 + 字号阶梯"抽成常量。

6. **RTS 具体数值缺口**：SC2 命令卡、AoE2 顶部栏的权威像素**公开资料查不到**（本次 40+ 关键词未命中，WebFetch 被网络策略阻断无法抓原站，也无截图可测）。若需要精确值，**两个可行路径**：a) 实测游戏截图（截 1080p 图 → 像素测量命令栏占比/图标 px）；b) 查官方 modding 资源（如 WC3 FDF、AoE2 mod 工具的 UI 定义文件）。
