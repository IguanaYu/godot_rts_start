## 二、关键决策链

### D1 方法论拆成多文档，不写一份大全
用户：不同任务需要参考查询不同文档。且用户新建了 docs/ 新架构（README 唯一入口 + 目录职责表），方法论归 `standards/`（"设计新东西时按什么标准"）。

### D2 《策划工作流方法论》设计（逐项拍板）
- 主体 = 五阶段线性流水线（技法、教训嵌在阶段里），不做技法字典
- **第 0 步目的澄清**（用户：一定要和我对齐想法，不然容易做跑偏）——任何任务必过
- 现状盘点并入调研层 → 六阶段并为五阶段
- 教训嵌入对应阶段，不设独立负面清单章
- 三代演进史：**完全砍掉**（用户选择，与 Claude 推荐相反）
- 加"任务规模→流程裁剪"表：阶段级走全流程 / bug 微调不进门
- 经济推演嵌在决策章一节，不独立成文

### D3 《调研工作方法》独立成文（从流水线文档拆出）
用户核心输入：**调研最重要的是目的先行**——"这个工作的目的是什么，哪些行为解决这个目的的哪些方面"，然后才是准则/要求/不能犯什么错，最后才是类似产品调研；**横向调研类似产品，纵向分析这个东西有没有发展历史**。

落成五层：目的层 → 现状层 → 横向层 → 纵向层 → 结论层。

- 纵向深度 = 机制级演化（2-3 个关键节点），不做完整谱系
- 纵向层实例**留空待实践补**（项目内无现成纵向调研先例，不为凑范例降低真实性）
- 通用准则现在就落 4 条：真实信息不编造（硬要求）、每案例带对本作的启示、先标杆后扩展、必须有结论
- **成本意识降级**（用户原话：成本意识可以略淡一点，先要求更好的结果，再说成本。结果不好聊成本不行的）——"范围失控"教训表述为"无效调研不服务于结论"，非"调研花太多"

### D4 《机制好坏判据》设计
- 定位 = 本项目实证判据（每条挂真实案例），与《玩法设计讨论方法论》（通用讨论工具）引用不收编
- 每条五段式：判据 / 案例 / 为什么坏 / 补救方向 / **边界（何时不适用）**
- **不分级**（不做"红线/警惕"两级，用户选择，与 Claude 推荐相反），弹性靠边界段表达
- 末尾留"待补充判据区"，用户后续玩法思考够格（有案例+边界）再转正

### D5 决策阶段标准三段式（用户核心输入）
"先言明利弊，然后谈可以的做法有哪些。尽量让我这边决策做选择题。"→ 落为：①言明利弊（两面展开）→ ②列出可选做法 → ③选择题拍板 + 编号记录。

## 三、过程约定

- 每份文档先由 Claude 出设计案（内容清单 + 写法 + 决策点）→ 用户评价/补充 → 用户说"问答"后再逐项提问拍板 → 写作。此流程本身即 D5 的实践。
- 实例真实性核验后才写作：写作前逐一核实了 audio_00 / T1 决策表 / T2 偏离记录 / T3 总览修正清单 / C 候选库的真实结构。
