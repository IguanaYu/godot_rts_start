## 二、核心交付

### 2.1 详情面板 L6-L9 多选场景

| 编号 | 场景 | 详情面板显示 |
|---|---|---|
| **L6** | 多选**异类**单位（步兵+弓兵）| 两类汇总（各自总数 + 各自汇总信息）|
| **L7** | 多选**同类**建筑（2 个兵营）| 汇总信息（总数 + 总血量百分比 + 在造进度）|
| **L8** | 混选建筑 + 单位 | **仅主单位**（最新选中的单位优先，建筑忽略）|
| **L9** | 框选单位 + 点建筑 | **切换为建筑详情 + 保留单位选中**（点回地图恢复单位汇总）|

### 2.2 灰色锁系统（应用到现有 tabbed QW 栏）

- **未到时代**：T2/T3 项显示锁（如玩家 T1 时，靶场/弓兵显示锁）
- **解锁条件**：城堡 age 升级到对应等级
- **解锁反馈**：升级完成时，相关项的灰色锁解除 + 高亮闪烁（极简反馈）

### 2.3 T3 升级入口

- T2 升完后，城堡详情面板自动出现"升级到 T3"按钮
- 按钮 ID 与"升级到 T2"一致，参数切换为 T2→T3
- T3 升级参数推到 T3 阶段（本 PR 只暴露入口）

## 四、实施步骤

### 步骤 1：L6 多选异类单位汇总（1h）

1. detail_panel.gd 加 `show_units_mixed(units: Array)` 方法
2. 内部按单位类型分组（步兵/弓兵/精英/...）
3. 详情面板内容：
```
┌──────────────────┐
│ 选中 8 个单位     │
│ ──────            │
│ ▸ 步兵 × 5        │
│   总 HP: 600      │
│   总 DMG: 60      │
│ ▸ 弓兵 × 3        │
│   总 HP: 180      │
│   总 DMG: 45      │
│ ▸ 科技（按主类型）│
│   (主类型 = 弓兵) │
└──────────────────┘
```
4. 主类型规则：数量最多的类型，若并列取最新选中

**验收**：框选 5 步兵 + 3 弓兵 → 详情面板分两段显示

### 步骤 2：L7 多选同建筑汇总（1h）

1. detail_panel.gd 加 `show_buildings_same_type(buildings: Array)` 方法
2. 详情面板内容：
```
┌──────────────────┐
│ 选中 2 个兵营     │
│ ──────            │
│ ▸ 现状            │
│   总数量: 2/5     │ ← 农场上限提醒
│   平均血量: 80%   │
│   在造: 3 兵      │
│   ▓▓▓░░░ 进度    │
│ ▸ 步兵科技        │ ← 仍显示步兵升级（同 L2）
│   [HP+][DMG+]     │
└──────────────────┘
```
3. 总血量 = 所有选中建筑当前 HP 之和 / 最大 HP 之和
4. 在造进度 = 所有选中建筑的产兵队列总和

**验收**：双击选所有兵营 → 详情面板显示汇总信息

### 步骤 3：L8 混选建筑+单位仅主单位（1h）

1. 在 main.gd 的 `_on_selection_changed` 区分：
   - 全是单位 → L3 或 L6
   - 全是建筑 → L2 或 L7
   - 混合 → **L8 仅主单位**（过滤掉建筑，按单位走 L3/L6）
2. 主单位 = 最新选中的单位（假设 selection 数组按选中顺序）
3. 建筑被忽略时，详情面板不显示建筑信息

**验收**：
- 框选包含建筑和单位 → 详情面板只显示单位
- 最新选中的单位优先显示

### 步骤 4：L9 框选+点建筑切换 + 保留选中（1.5h）

1. combat_controller.gd 加"临时查看建筑"模式：
   - 单位选中状态保留（selected_units 数组不空）
   - 点击建筑时，进入 "peeking" 状态：详情面板切到建筑，但 selected_units 保留
2. 点回地图空地 → 退出 peeking，详情面板恢复显示 selected_units 汇总（L6/L7）
3. 点另一个建筑 → 切换 peeking 目标
4. 点单位 → 替换选中（恢复正常选区逻辑）

**关键状态**：
- `selected_units: Array`（保留）
- `peek_target: Node`（临时查看的建筑，可为空）

**验收**：
- 框选 5 步兵 → 详情显示步兵汇总
- 点击地图兵营 → 详情切到兵营，5 步兵仍选中
- 点回空地 → 详情恢复步兵汇总
- 点单位 → 选中替换为该单位

### 步骤 5：灰色锁系统（1h）

1. 在 game_ui.gd 的 `_add_icon_button` 加参数 `is_locked: bool`
2. 锁状态视觉：
   - 锁图标（小锁 TextureRect 叠加在按钮右上）
   - 按钮变灰（modulate.a = 0.5 或专门灰色 shader）
   - 点击不响应（或提示 "LOCKED_NEED_AGE_T2"）
3. 锁状态判断：
   - 读取 building_stats / unit_stats 的 `unlock_age` 字段（PR-T2-1 暴露的 age 状态对比）
   - 兵营/步兵/农场/箭塔 unlock_age = T1（默认）
   - 靶场/弓兵 unlock_age = T2
   - 修道院/僧侣 unlock_age = T3（如未来加）
4. PR-T2-1 的 `age_changed` 信号触发时，刷新所有 QW 按钮的锁状态

**验收**：
- T1 阶段 QW 中靶场/弓兵显示锁
- 升 T2 后，靶场/弓兵锁解除（变正常 + 高亮闪烁）
- T3 项仍显示锁（玩家 T2 时）

### 步骤 6：T3 升级入口（30min）

1. 在 detail_panel.gd 的城堡详情分支加判断：
   - age = T1 → 显示"升级到 T2"按钮
   - age = T2 → 显示"升级到 T3"按钮（参数切换）
   - age = T3 → 不显示时代升级按钮
2. T3 升级参数（费用/时间/反还）暂用占位（如 1000 金/30s/反还 500），T3 阶段拍板时改
3. 升级逻辑复用 PR-T2-1 的 `start_age_upgrade(AGE.T3)` API

**验收**：
- T1 城堡详情显示"升级到 T2"
- 升完 T2 后，详情自动变成"升级到 T3"
- 升完 T3 后，时代升级按钮消失

### 步骤 7：测试 + 微调（30min）

1. 测试 L1-L9 全部切换场景
2. 测试 QW 在 T1/T2/T3 三个时代的灰色锁表现
3. 测试灰色锁与现有快捷键不冲突（Q+1 是否还能造兵）

## 六、风险与注意事项

### 6.1 高风险
- **L9 peeking 模式与现有选区逻辑冲突**：现有 combat_controller.gd 的选区是"独占式"（一次只选一类）。加 peeking 模式要小心，避免破坏框选/双击选同类等现有功能。建议加 `_peek_target` 字段独立管理，不改 selected_units
- **灰色锁判断的 unlock_age 字段**：现有 stats 没有 unlock_age 字段（PR-T2-1 应该没加到 stats 上）。本 PR 要在 building_stats.gd / unit_stats.gd 加这个字段，或集中维护在某 manager 里。灰色锁只落在现有 tabbed QW 栏，不改快捷键映射

### 6.2 中风险
- **T3 升级入口的占位参数**：T3 升级费用/时间未拍板，本 PR 用占位。T3 阶段拍板后再改参数
- **混选时 L8 主单位的"最新选中"判断**：需要 selection 数组按选中顺序排序。现有 selected_units 是否保留顺序要确认（如不保留，需要新增 _selection_order 数组）

### 6.3 注意事项
- **节点命名**：灰色锁用 `LockIcon` 子节点，避免与现有按钮装饰冲突
- **国际化**：锁状态提示文案用 key（如 `LOCKED_NEED_AGE_T2`）
- **QW 快捷键冲突**：Q 切单位、W 切建筑、Q+1 造步兵... 这套快捷键要保持工作。加灰色锁时不要破坏 `_handle_qw_shortcut` 类函数
