## 一、本 PR 目标

把"哪些单位/建筑在哪个时代解锁"的结构调整到 T3 决策稿要求：

| 时代 | 单位 | 建筑 |
|---|---|---|
| **T1** | 步兵 | 兵营、塔、墙、农场、城堡 |
| **T2** | 弓兵 + **僧侣**（新增 T2 解锁） | 靶场 + **修道院**（新增 T2 解锁） |
| **T3** | **长矛兵**（挪到 T3 解锁） | T3 学院（PR-2 实施） |

**不动的**：
- 长矛兵的生产建筑 = 现有 BARRACKS（不新建"长矛兵营"）
- map_config.available_items（战前编制）不动；时代过滤在 unlocked_items 层做

## 二、改动清单

### 2.1 改 `scripts/main.gd` `_init_unlocked_items()`（L1710-1718）

**改前**：
```gdscript
func _init_unlocked_items() -> void:
    unlocked_items.clear()
    var source: Array = D.ALL_ITEMS
    if map_config != null and not map_config.available_items.is_empty():
        source = map_config.available_items
    for mode in source:
        var m: int = int(mode)
        if m != D.PlaceMode.ARCHERY_RANGE and m != D.PlaceMode.ARCHER:
            unlocked_items.append(m)
```

**改后**：
```gdscript
func _init_unlocked_items() -> void:
    unlocked_items.clear()
    var source: Array = D.ALL_ITEMS
    if map_config != null and not map_config.available_items.is_empty():
        source = map_config.available_items
    # T1 阶段过滤掉所有非 T1 内容
    # - ARCHERY_RANGE / ARCHER ：T2 解锁
    # - MONASTERY / MONK_UNIT  ：T2 解锁（T3 PR-1 调整）
    # - LANCER                  ：T3 解锁（T3 PR-1 调整）
    var t1_filtered := {
        D.PlaceMode.ARCHERY_RANGE: true,
        D.PlaceMode.ARCHER: true,
        D.PlaceMode.MONASTERY: true,
        D.PlaceMode.MONK_UNIT: true,
        D.PlaceMode.LANCER: true,
    }
    for mode in source:
        var m: int = int(mode)
        if not t1_filtered.has(m):
            unlocked_items.append(m)
```

**为什么用 Dictionary 而不是 `or` 链**：随着时代挪动的项增多，`or` 链可读性差；Dictionary 显式列出过滤项，便于后续扩展。

### 2.2 改 `scripts/main.gd` `_unlock_age_items(age)`（L1212-1221）

**改前**：
```gdscript
func _unlock_age_items(age: int) -> void:
    var to_unlock: Array[int] = []
    if age >= 2:
        to_unlock = [D.PlaceMode.ARCHERY_RANGE, D.PlaceMode.ARCHER]
    for mode in to_unlock:
        var m: int = int(mode)
        if m not in unlocked_items:
            unlocked_items.append(m)
    ui_module.update_gold_display(gold)
```

**改后**：
```gdscript
func _unlock_age_items(age: int) -> void:
    var to_unlock: Array[int] = []
    if age >= 2:
        # T2 解锁：靶场 + 弓兵 + 修道院 + 僧侣
        to_unlock = [
            D.PlaceMode.ARCHERY_RANGE,
            D.PlaceMode.ARCHER,
            D.PlaceMode.MONASTERY,
            D.PlaceMode.MONK_UNIT,
        ]
    if age >= 3:
        # T3 解锁：长矛兵（沿用 BARRACKS 生产线，不新建长矛兵营）
        to_unlock.append(D.PlaceMode.LANCER)
    for mode in to_unlock:
        var m: int = int(mode)
        if m not in unlocked_items:
            unlocked_items.append(m)
    ui_module.update_gold_display(gold)
```

### 2.3 detail_panel.gd **不需要改**

[detail_panel.gd:207-211](../../scripts/ui/detail_panel.gd#L207) 当前 BARRACKS 详情面板硬编码调用 `_add_produce_button(SOLDIER)` + `_add_produce_button(LANCER)`。

[`_add_produce_button` 第 253-254 行](../../scripts/ui/detail_panel.gd#L253) 已经按 `unlocked_items` 过滤：

```gdscript
func _add_produce_button(mode: int) -> void:
    if int(mode) not in _main_node.unlocked_items:
        return
    ...
```

所以 T1 阶段 LANCER 不在 `unlocked_items` 里 → 按钮自动不显示。T3 升级后 LANCER 进入 `unlocked_items` → 按钮自动出现。**这是机制层面的"自动过滤"，无需 UI 改动**。

### 2.4 测试关卡 map_config 检查

**任务**：检查测试关卡的 `.tres` 文件，确认 `available_items` 字段。

**文件路径**：
- `resources/map_test_outpost_config.tres`（或同名文件）
- 其他测试关卡配置

**检查项**：
1. `available_items` 是否为空（默认）—— 空表示用 ALL_ITEMS
2. 如果配置了具体项，确认是否包含 MONASTERY/MONK_UNIT/LANCER —— 如果包含，玩家战前编制能选；不包含则玩家根本选不到这些单位

**重要**：本 PR **不强制改测试关卡的 available_items**。如果想让测试关卡能完整体验 T3 内容，建议把所有单位都加进编制；但即使不加，时代挪动的逻辑也是生效的（编制里有但时代没解锁的，进游戏造不了）。

**操作步骤**：
1. 用 Glob 找出所有 `resources/*config.tres`
2. 逐个 Read，查 `available_items` 字段
3. 如果字段为空或包含全部单位：不动
4. 如果字段只配置了 SOLDIER：记录到本 PR 末尾"冲突记录"段落，问人类是否要改

## 六、风险与已知问题

### 风险 1：map_config.available_items 覆盖逻辑

**现状**：[`_apply_loadout_filter` (main.gd:1695-1705)](../../scripts/main.gd#L1695) 会用战前编制覆盖 `map_config.available_items`。

**影响**：如果玩家战前编制里没有 LANCER/MONK_UNIT/MONASTERY，那 `available_items` 不包含这些，`_init_unlocked_items` 用 `source = map_config.available_items` 时，连过滤都不需要（因为编制里根本没有）。

**结论**：本 PR 改动对"使用战前编制的关卡"是冗余但安全的。对"不使用战前编制的关卡"（available_items 为空，用 ALL_ITEMS）才是必要的。

**记录到 PR 末尾**：执行者请在测试报告中注明测试关卡是哪种模式。

### 风险 2：BARRACKS stats.tres 的 production_variant_ids

[building_stats.gd L24](../../scripts/stats/building_stats.gd#L24) 有 `production_variant_ids` 字段。如果 BARRACKS 的 stats.tres 配置里包含 lancer，建筑行为可能受影响。

**验证步骤**：
1. 找到 BARRACKS 的 stats.tres（应在 `scenes/buildings/barracks/stats.tres` 或 `resources/stats/`）
2. 读取 `production_variant_ids`
3. 如果包含 lancer，**记录但不动**（实际生产是 detail_panel 按钮触发的，不会自动产 lancer）
