## 一、Context

PR-T2-3 是 T2 阶段**最关键的 UI 改造**：把分散的目标面板（右上）+ 小地图（右下）整合到屏幕右侧统一信息柱，中间 55% 留给详情面板。详情面板 L1-L5 是基础切换场景，L6-L9 多选场景留给 PR-T2-5。

**前置依赖**：无（PR-T2-1/2 已做但本 PR 不直接依赖其机制，只要 age 状态能读到即可）

**后续依赖**：PR-T2-4（升级按钮挂详情面板）、PR-T2-5（L6-L9 多选场景）

## 二、核心交付

### 2.1 右侧信息柱框架（屏宽 20% ≈ 384px）

```
┌────────────────────────────────────────┐
│ 资源(左上)                              │
│                                ┌──────┐│
│                                │目标  ││ ← 顶部 15%
│        [游戏世界]              │波次  ││
│                                ├──────┤│
│                                │详情  ││ ← 中部 55%
│                                │面板  ││   （主要操作区）
│                                │      ││
│                                │      ││
│                                ├──────┤│
│                                │小地图││ ← 底部 30%
│        ┌──────────────┐        │      ││
│        │ QW 建造栏     │        │      ││
│        └──────────────┘        └──────┘│
└────────────────────────────────────────┘
```

- 信息柱宽度：屏宽 × 20%（1920 下 384px，1280 下 256px）
- 信息柱位置：屏幕右侧，从顶到底
- 三段式高度分配：
  - 目标面板：信息柱高度 × 15%
  - 详情面板：信息柱高度 × 55%
  - 小地图：信息柱高度 × 30%
- QW 建造栏：**保持现状 200px 不变矮**（08-06 决策）

### 2.2 通用详情面板模板

```
┌──────────────────┐
│ {标题}            │ ← 标题区（图标 + 名称）
│ ──────            │
│ ▸ 现状            │ ← 现状区（HP/DMG/数量等）
│   {动态内容}      │
│ ▸ 科技 / 升级     │ ← 科技区（PR-T2-4 接入，本 PR 占位）
│   {占位 Label}    │
└──────────────────┘
```

模板要点：
- **标题区**：图标 + 名称（多选时显示总数）
- **现状区**：根据对象类型动态填充
- **科技区**：本 PR 先放占位 Label "T2 升级待接入"，PR-T2-4 替换为升级按钮

## 四、实施步骤

### 步骤 1：搭右侧信息柱容器（1.5h）

1. 新建 `scripts/ui/right_info_column.gd`，extends CanvasLayer 或 Control
2. 在 `game_ui.gd` 的 `_create_ui()` 中创建容器，锚定 PRESET_RIGHT_WIDE（或手动设 anchor_right=1.0/anchor_top=0/anchor_bottom=1.0，宽度屏宽 20%）
3. 容器内 VBoxContainer，三个子节点：top_panel（目标）+ detail_panel（详情）+ bottom_panel（小地图），高度比例 15/55/30
4. 跑游戏确认布局正确（详情区先放 Label "T2 详情面板待实现"）

**验收**：屏幕右侧出现三段式容器，1920 分辨率下宽 384px，三段比例正确。

### 步骤 2：迁移目标面板（30min）

1. 把 `objectives_panel.gd` 从独立 CanvasLayer 改成 right_info_column 的 top_panel 子节点
2. 移除 objectives_panel 的 PRESET_TOP_RIGHT 锚定
3. 调整 objectives_panel 内部布局以适配新尺寸（宽度从 240 变成 ~384）
4. 跑游戏确认目标面板在新位置显示正常（波次倒计时、星级进度等）

**验收**：目标面板在右侧顶部，宽度 ~384，内容不溢出。

### 步骤 3：迁移小地图（30min）

1. 把 `minimap_panel.gd` 从 game_ui.gd 创建的 Control 改成 right_info_column 的 bottom_panel 子节点
2. 移除原 PRESET_BOTTOM_RIGHT 锚定
3. 调整 minimap 内部尺寸（保持正方形比例，宽度 ~384 应该够）
4. 跑游戏确认小地图在新位置显示正常（标记、点击导航等）

**验收**：小地图在右侧底部，内容正常。

### 步骤 4：通用详情面板模板（1h）

1. 新建 `scripts/ui/detail_panel.gd`，extends Control（挂在 right_info_column 的 detail_panel 节点）
2. 内部结构：标题区（HBoxContainer：图标 + Label）+ 现状区（VBoxContainer）+ 科技区（VBoxContainer 占位）
3. 提供 API：
   - `show_default()`：显示默认状态（L1 城堡详情）
   - `show_building(building)`：显示建筑详情（L2）
   - `show_unit(unit)`：显示单位详情（L3）
   - `show_temporary(content_builder)`：临时切换（L4 hover）
   - `restore_previous()`：恢复之前选中（L4 移开）
4. 跑游戏确认模板能渲染空内容

**验收**：详情面板能切换不同状态，标题/现状/科技区清晰分隔。

### 步骤 5：L1 默认状态 + L2 单建筑 + L3 单单位（2h）

1. 实现 `show_default()`：找到玩家城堡（team=PLAYER + building_type=CASTLE），显示其详情
2. 实现 `show_building(building)`：
   - 城堡：HP/时代/升级按钮（占位）
   - 兵营：HP/在造进度
   - 靶场：HP
   - 农场：HP/产能
   - 箭塔：HP/攻击力/射程
3. 实现 `show_unit(unit)`：
   - 步兵：HP/DMG/SPD
   - 弓兵：HP/DMG/射程
4. 在 main.gd 的 `_on_selection_changed()` 里调用 detail_panel 的 show_building / show_unit
5. 点空地（无选中）→ 调用 `show_default()`

**验收**：
- L1 启动时详情面板显示城堡
- L2 点地图建筑 → 详情切换
- L3 点地图单位 → 详情切换
- 点空地 → 恢复 L1

### 步骤 6：L4 hover QW 图标临时切换（1h）

1. 在 game_ui.gd 的 `_add_icon_button()` 给 QW 按钮连接 `mouse_entered` / `mouse_exited` 信号
2. `mouse_entered` → 调用 `detail_panel.show_temporary(...)`，显示该按钮对应建筑/单位的详情（灰色版本，提示"未建造"或"未生产"）
3. `mouse_exited` → 调用 `detail_panel.restore_previous()`，恢复之前选中
4. 内部状态管理：`current_mode`（PERMANENT / TEMPORARY）+ `permanent_state`（保存之前选中）

**验收**：
- 鼠标移到 QW 图标 → 详情面板临时切换
- 移开 → 恢复之前选中
- 没选中时 hover QW → 显示该图标详情，移开 → 回 L1 默认

### 步骤 7：L5 升级时城堡头顶进度条 + 详情保持（30min）

1. 监听 PR-T2-1 的 `age_upgrade_started` 信号
2. 升级启动时：
   - 城堡头顶出现进度条（参考 `_production_circle` 的实现）
   - 详情面板**保持显示城堡**（如选中是城堡，不变；如选中是其他对象，自动切到城堡）
3. 升级完成 / 取消时：进度条消失，详情面板保持当前选中

**验收**：
- 点"升级到 T2"按钮 → 城堡头顶出进度条
- 详情面板保持城堡详情
- 升级完成 → 进度条消失，详情面板仍显示城堡（age=T2）

### 步骤 8：测试 + 修补（30min）

1. 切换不同分辨率（1920/1600/1280）确认布局自适应
2. 测试 L1-L5 切换顺序：默认 → 选单位 → 选建筑 → 点空地 → hover QW → 升级
3. 修复发现的问题

## 六、风险与注意事项

### 6.1 高风险
- **目标面板 + 小地图迁移破坏现有锚点**：现有 objectives_panel 用 PRESET_TOP_RIGHT，minimap_panel 用 PRESET_BOTTOM_RIGHT，迁移到新容器要重新调整内部锚点。建议用 git diff 对比迁移前后布局。
- **1280 分辨率下信息柱偏窄**：1920 下 384px 够，1280 下只有 256px。建议设置 minimum_width=300，过窄时游戏世界可视区域让步。

### 6.2 中风险
- **L4 hover 实现细节**：现有 QW 按钮在 `_add_icon_button()` 创建，需要在该函数里加 mouse_entered/exited 信号连接。注意 button_factory.gd 的封装不要破坏。
- **L5 升级时强制切到城堡**：用户选中其他单位时启动升级，是否强制切到城堡？建议**不强制**（只在用户当前选中是城堡或空地时切换；选了其他单位时维持，避免打断操作）。

### 6.3 注意事项
- **不要复用 `_production_circle`**：城堡头顶升级进度条要新建独立节点（如 `_age_upgrade_progress`），避免与产兵进度冲突。
- **预留科技区插槽**：详情面板的科技区是个独立 VBoxContainer，PR-T2-4 会往里面塞升级按钮。本 PR 用占位 Label 标记位置。
- **国际化键**：所有新文案用 translations.csv 的 key，不要硬编码中文。
- **节点命名**：新建节点用清晰名字（如 `RightInfoColumn` / `DetailPanel` / `DetailContent_*)`），避免 get_children() 遍历找节点时误匹配。
