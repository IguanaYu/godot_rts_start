## 三、T1 测试地图规格（核心）

### 3.1 总体设计原则

**目标**：提供一张**纯净、可控、可复现**的测试地图，专门验证 T1 经济机制、骚扰节奏、SH1 占领。

**为什么新建而不复用**：
- 现有 20 关都引入了多机制（多据点、AI 盟军、星级条件），干扰隔离测试
- 现有 4 个 test_outpost 场景过于专项（只测据点），没有经济+骚扰+据点的完整闭环
- 测试关卡模式可自由访问，无解锁限制

**地图名**：`T1 经济与骚扰测试`（`map_t1_economy_test`）

### 3.2 地图基本信息

| 项目 | 值 | 备注 |
|---|---|---|
| 场景文件 | `scenes/maps/map_t1_economy_test.tscn` | 新建 |
| 配置文件 | `resources/map_t1_economy_test_config.tres` | 新建 |
| 地图尺寸 | `Rect2(0, 0, 1500, 1000)` | 中等大小，玩家徒步横穿 ~12 秒 |
| 导航边界 | 整张地图（除障碍物） | 4 顶点 |
| 相机起始 | `Vector2(200, 500)` | 玩家城堡位置 |
| 地形主题 | 0（默认草地） | |
| 环境物体 | `{trees: 8, rocks: 5, bushes: 6, sheep: 3}` | 轻量装饰，不干扰战斗 |
| balance_scheme | 2（SLOW） | 与 [project_balance_scheme.md](../sessions/2026-07-28_玩法推进纪要.md) 一致 |

### 3.3 玩家初始状态

**初始金币**：`400`（T1 设计基准，NORMAL 难度）

**初始建筑**：
```gdscript
player_buildings = [
    {"type": 3, "grid_pos": Vector2i(3, 8)}    # CASTLE 城堡，左下角
]
```

**初始单位**：
```gdscript
player_units = [
    {"type": 5, "pos": Vector2(150, 450)},     # 1 个步兵（探索用）
    {"type": 5, "pos": Vector2(150, 550)}      # 1 个步兵（防守用）
]
```

**available_items**（玩家可建造/生产）：
```gdscript
available_items = [
    1,    # WALL → FARM（农场）
    2,    # TOWER（箭塔）
    4,    # BARRACKS（兵营）
    5,    # SOLDIER（步兵）
    6,    # ARCHER（弓兵）

```

⚠️ **不包含**：CASTLE（不可造）、MONASTERY（T1 用不到）、ARCHERY_RANGE（先简化，T2 阶段再加）、所有 T2/T3 单位。

### 3.4 敌方初始状态

**初始建筑**（作为骚扰来源 + 最终目标）：
```gdscript
enemy_buildings = [
    {"type": 3, "grid_pos": Vector2i(28, 8)}   # 敌方 CASTLE，右下角

```

**初始单位**：空（骚扰完全由 WaveManager 调度）

**敌方城堡 HP**：调高到 1500（默认 1000），让玩家无法速推，必须先吃 SH1。

**据点半径**：`territory_radius = 200`（约 5 格）

# SH1 守军单位（场景启动时生成）

    {"type": 6, "pos": Vector2(750, 460)},   # 弓兵 1

**OutpostCommander 节点**：

- `commander_uid = &"sh1_outpost"`
- `alliance_id = 1`（敌方）
- `territory_radius = 200`
- `aggression = 0.4`（防守型，不主动出击）
- `defensiveness = 0.7`
- `enabled_spells = []`（T1 阶段据点不施法，简化）
- `enabled_strategies = []`

**占领触发**（待实施）：在 `outpost_commander.gd` 新增信号：
- `outpost_captured(alliance_id)` —— 当范围内所有敌方建筑 + 单位清空时 emit

### 3.6 骚扰波次配置（WaveManager）

**调度策略**：每波提前 30 秒警告（objectives_panel 显示倒计时）。

| 波次 | 时间 | 单位组成 | 总 DPS | 目标 |
|---|---|---|---|---|
| 1 | 1:30 | 3 步兵 | 50 | 玩家城堡 |
| 2 | 3:30 | 4 步兵 + 1 弓兵 | 75 | 玩家城堡 |
| 3 | 5:30 | 6 步兵 + 2 弓兵 + 1 精英 | 128 | 玩家城堡 |
| 4 | 7:30 | 8 步兵 + 3 弓兵 + 2 精英 | 194 | 玩家城堡 |

**生成位置**：敌方城堡周围（`Vector2(1300, 500)` 附近）

**行为**：`wave_attack = true`，目标 `Vector2(200, 500)`（玩家城堡）—— 路过打单位 + 到达后攻击城堡

**配置示例**（在场景 _ready 注入 WaveManager）：
```gdscript
waves = [
    {delay=90.0, wave_attack=true, wave_target=Vector2(200, 500),
     groups=[{type=5, count=3, stats_id=&"soldier"}]},
    {delay=120.0, wave_attack=true, wave_target=Vector2(200, 500),
     groups=[{type=5, count=4, stats_id=&"soldier"},
             {type=6, count=1, stats_id=&"archer"}]},
    {delay=120.0, wave_attack=true, wave_target=Vector2(200, 500),
     groups=[{type=5, count=6, stats_id=&"soldier"},
             {type=6, count=2, stats_id=&"archer"},
             {type=5, count=1, stats_id=&"elite_vanguard"}]},
    {delay=120.0, wave_attack=true, wave_target=Vector2(200, 500),
     groups=[{type=5, count=8, stats_id=&"soldier"},
             {type=6, count=3, stats_id=&"archer"},
             {type=5, count=2, stats_id=&"elite_vanguard"}]},
]
```

⚠️ `elite_vanguard` 是占位 stats_id，需在 [resources/stats/](../../resources/stats/) 新建（HP 150 / ATK 18 / 速度 100 / scale 1.2）。

### 3.7 指挥官选择

**强制问题**：现有系统强制选指挥官，默认 `balanced`（带 economy_boost 经济被动）。

**T1 测试推荐**：`test_all`（无加成白板）

⚠️ **风险**：`test_all` 需要首次胜利才解锁。

**应对方案**（按优先级）：
1. **方案 A**（推荐）：在 `level_select.gd` 加载本地图时，强制覆盖 `CommanderChoice.player_selected_id = "test_all"`（仅本测试地图生效）
2. **方案 B**：在 SaveManager 预解锁 test_all
3. **方案 C**：新建 `commander_test_basic.tres`（白板指挥官，无经济加成、无被动）—— 工作量大，不推荐 T1 阶段做

### 3.8 难度推荐

**测试默认**：NORMAL（gold_mult = 1.0）

| 难度 | 测试用途 |
|---|---|
| EASY | 验证"新手延迟"流程（gold_mult 1.25 → 开局 500 金）|
| NORMAL | 主验证（开局 400 金）|
| HARD | 验证"高压"流程（gold_mult 0.75 → 开局 300 金）|

### 3.9 胜负条件 + 星级

**胜利条件**：摧毁敌方城堡（type=3 在 enemy_buildings）

**失败条件**：玩家城堡被摧毁

**星级**（可选，T1 测试不强求）：
```gdscript
star_time_3 = 600.0       # 3 星：< 10 分钟
star_time_2 = 900.0       # 2 星：< 15 分钟
star_deaths_3 = 5         # 3 星：单位死亡 ≤ 5
star_deaths_2 = 15        # 2 星：单位死亡 ≤ 15
```

## 七、起手 PR 建议

### 7.1 强烈推荐：从 PR-1（阶段 0 + 1）起手

**理由**：
- 阶段 0.1 字段是所有后续改动的依赖
- 阶段 1 完成后即可验证核心经济数值（不需 UI、不需骚扰）
- 改动集中在 5-8 个文件，单次 PR 可控
- 风险最小（无 UI 改动、无新机制，只是字段化）

**PR-1 预计改动文件**：
1. `scripts/stats/building_stats.gd`（加 5 字段）
2. `scripts/systems/game_data.gd`（WALL → FARM 改名 + COSTS 改步兵）
3. `resources/stats/buildings/wall_stats.tres` → `farm_stats.tres`
4. `scenes/buildings/wall.tscn` → `farm.tscn`
5. `resources/stats/buildings/castle_stats.tres`（加 gold_production_amount）
6. `resources/stats/buildings/barracks_stats.tres`（加 completion_refund_unit）
7. `scripts/buildings/building.gd`（产金数据驱动）
8. `scripts/systems/building_placer.gd`（动态造价 + 完成反还 hook）

### 7.2 不推荐起手方式

- ❌ 直接做阶段 4（SH1 据点）—— 依赖太多，难度大
- ❌ 直接做阶段 2（操作端 UI）—— 经济数值未对齐前，UI 验证无意义
- ❌ 一次性做 PR-1 + PR-2 —— 改动过大，review 困难

### 7.3 验证 PR-1 成功的最小测试

进入 `map_t1_economy_test`（即使阶段 5 还没做完，可临时挂在 stress_test.tscn 上验证）：
