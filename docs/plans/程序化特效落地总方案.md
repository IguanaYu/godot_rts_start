## 1. 基础能力升级（前置）

这部分是后续所有特效建议的"共同依赖"，建议先落地。对应调研报告的 P0 三件套 + shader 接入修复。

### 1.1 unit_effects.gdshader 未接入 uniform 修复

**现状问题**：`unit_effects.gdshader` 留了 12 个 uniform，但 5 个未接入代码：
- `hit_flash_enabled` / `hit_flash_color` / `hit_flash_amount` — 受击白闪
- `enraged_enabled` / `enraged_tint` — 狂暴
- `blessed_enabled` / `blessed_tint` — 祝福
- `boss_glow_enabled` / `boss_glow_color` / `boss_pulse_speed` — Boss 发光

**接入点**（参考 [单位动态与状态视觉设计方案.md](单位动态与状态视觉设计方案.md) "Shader 方案" 一节）：
- `unit.gd::take_damage()` → 触发 `hit_flash_amount` 从 0 → 0.85 → 0（约 0.12 秒 Tween）
- `unit.gd::_init_outline_materials()` 已为每单位 `material.duplicate()`，per-instance 隔离没问题，不会踩"一个受击全部闪"的坑（参考调研报告 2.2）
- 狂暴/祝福/Boss 发光等持续状态，由对应技能/buff 系统调用 `set_shader_parameter()` 启停

**配置说明**：不需要在 Inspector 配置，全部走代码接入。如果某单位需要差异化颜色（比如烈焰僧侣的 hit_flash 是红色而非白色），可以在单位 stats 加 `hit_flash_color_override: Color` 字段。

### 1.2 Dissolve 消散 shader（新增）

**来源**：[调研报告 1.2](程序化动画与特效调研报告.md) 

**为什么前置**：单位死亡、召唤物出生、闪现、传送门这些场景全都要 dissolve。一个 shader 一次性解决。

**实现要点**：
- 在 `shaders/` 新增 `dissolve.gdshader`，或者把 dissolve 逻辑合并进 `unit_effects.gdshader`（推荐后者，避免每单位挂两个 ShaderMaterial）
- 噪声纹理用 Godot 内置 `NoiseTexture2D` + `FastNoiseLite` 在编辑器内生成，存成 `.tres` 复用
- GDScript 驱动：`set_shader_parameter("dissolve_amount", x)` + Tween 从 0→1 或 1→0

**接入示例**（伪代码，落地时按实际接口调整）：
```gdscript
# unit.gd::die() 里把现有的 scale-to-zero 替换/叠加为：
var mat = body_sprite.material as ShaderMaterial
mat.set_shader_parameter("dissolve_amount", 0.0)
var tw := create_tween()
tw.tween_property(mat, "shader_parameter/dissolve_amount", 1.0, 0.4)
tw.tween_callback(queue_free)
```

**配置说明**：
- 死亡消散：`dissolve_amount` 0→1，0.4 秒，边缘色橙红
- 召唤出生：`dissolve_amount` 1→0，0.6 秒，边缘色紫蓝
- 闪现：起点消散（0.3 秒）+ 终点出现（0.3 秒）

### 1.3 粒子对象池系统（新增）

**来源**：[调研报告 3.3](程序化动画与特效调研报告.md)

**为什么前置**：RTS 同屏几十上百单位，每次受击/死亡都 `instantiate()` 粒子场景会卡顿（GitHub Issue #104360 实锤）。这是必须先做的基础设施。

**实现要点**：
- 新增 `scripts/effects/particle_pool.gd`（Autoload 单例）
- 接口：`prewarm(scene, count, key)` / `spawn(key, pos)` / 内部 `_return_to_pool()`
- 在 `main.gd::_ready()` 启动时预热所有常用粒子场景（命中火花、灰尘、爆炸碎片、治疗光斑）各 20-30 个

**接入示例**（参考调研报告 3.3 的代码模板）：
```gdscript
# main.gd::_ready()
ParticlePool.prewarm(load("res://scenes/effects/dust_effect.tscn"), 30, "dust")
ParticlePool.prewarm(load("res://scenes/effects/hit_spark.tscn"), 20, "hit_spark")
# ...

# 任意触发处
ParticlePool.spawn("dust", global_position)
```

**配置说明**：
- 预热数量根据实测调整（开局先各 20 个，跑大规模战斗测试时观察是否够用）
- 持续型粒子（如能量雾环、护盾环）不走池，直接挂单位子节点

**来源**：[调研报告 3.2](程序化动画与特效调研报告.md)

| 灰尘 | 单位落地/出生 | amount=8, gravity=(0,-15), spread=30° |
| 命中火花 | 近战命中 | amount=15, gravity=(0,200), explosiveness=0.8, additive |
| 碎片 | 建筑/城墙摧毁 | amount=12, gravity=(0,400), spread=180° |
| 能量雾 | 召唤/Buff | amount=20, additive, 蓝紫色 |

| 治疗光斑 | 僧侣治疗 | amount=15, additive, 金色向上 |
| 屏幕冲击波 | 大招/爆炸 | amount=1, 大半径圆环 |

### 2.1 基础兵种通用状态机

**适用范围**：剑士 / 弓兵 / 枪兵 / 僧侣的所有玩家方变体。变体专属视觉见 2.2。

| 状态 | 现状 | 建议 |
|---|---|---|
| **出生（spawn）** | ✅ 出生光柱 + 死亡缩小 | 加 `scale.y: 0.2 → 1.0`（ease-out back）落地弹性 + 脚下一圈**灰尘粒子**（ParticlePool.spawn("dust", pos)） |

### 2.2 T3 变体专属视觉

**适用范围**：玩家方 10 个 T3 变体。基础状态继承 2.1，本节只列**变体差异化**。

#### 剑士系

| 变体 | 差异化建议 |
|---|---|
| **狂战士** | HP 越低攻击越高 → HP < 50% 时接入 `enraged_enabled` + 红色描边脉动；攻击时多一次小幅度前冲（叠加在通用前冲上） |
| **盾卫** | 防御姿态时脚下蓝白护盾环持续；受击时优先走"护盾承伤"逻辑（即使 shield_hp = 0 也走蓝白环，体现"举盾"） |
| **复仇者**（如果有）| HP < 30% 时加红色愤怒描边（区别于狂战士的 enraged tint，用更深的红 + 描边更粗） |
| **决斗者**（如果有）| 锁定目标时加金色目标连线（类似 aggro_line 但颜色金色，表"1v1 决斗"）|

#### 弓兵系

| 变体 | 差异化建议 |
|---|---|
| **神射手** | 攻击前摇加长（蓄力）→ 蓄力期间脚下金色聚能光圈；箭矢带光迹（复用 arrow_trail 但加强） |
| **杀手射手** | 锁定英雄/Boss 时，目标脚下加红色目标标记（地面 _draw 圆环）|
| **减速射手** | 命中时加**冰晶爆裂粒子**（白色 + 浅蓝 + 短寿命）+ 短暂冰霜贴图叠加（0.3 秒）|

#### 枪兵系

| 变体 | 差异化建议 |
|---|---|
| **精英长矛** | 待机时轻微立姿（scale.y +1%）；锁定 Boss 时脚下金色目标环 |
| **Boss 杀手** | 攻击命中时加**贯穿冲击线**（从命中点向攻击反方向画一条 0.1 秒的线，表"穿甲"）|

#### 僧侣系

| 变体 | 差异化建议 |
|---|---|
| **神圣者**（群体治疗）| 治疗触发时加**金色十字光环**（地面 _draw，扩散 0.3 秒）+ 治疗光斑粒子 |
| **祝福者** | 持续金色光环（接入 `blessed_enabled` + 脚下细环）；buff 友军时友军脚下闪一次金色环 |

> **注**：上表是设计建议。具体变体能力（HP<50% 狂暴、对 Boss 加成等）需要核对 `resources/stats/t3_*_stats.tres` 里的实际字段。如果某个变体没对应的 gameplay 机制，差异化视觉就不做。

### 2.5 玩家指挥官技能（8 个）

**现状通病**：大多只有飘字提示，缺少"释放瞬间"和"持续效果"的世界内视觉。

| 技能 | 现状 | 建议 |
|---|---|---|
| **嘲讽** | 飘字 | **释放瞬间**：以施法者为中心的红色波纹环（地面 _draw 扩散 0.3 秒）<br>**持续效果**：被嘲讽的敌人头顶加红色感叹号标记（替代或叠加现有 aggro_line）|
| **闪现** | 飘字 + alpha | **起点**：dissolve 消散（0.3 秒）+ 紫色波纹<br>**终点**：dissolve 出现 + 紫色光柱<br>**轨迹**：起点到终点的紫色光迹（0.2 秒淡出）|
| **隐身** | 飘字 + alpha 变化 | 进入隐身：**dissolve + 横向扭曲**（不只是 alpha，更像"光化解构"）<br>退出隐身：反向 |
| **劝化** | 飘字（引导类）| **引导期间**：施法者到目标之间金色光柱（持续，地面 _draw）<br>**成功瞬间**：目标单位脚下金环扩散 + 接入 `blessed_enabled` 0.5 秒 |
| **护盾** | 飘字 | **释放瞬间**：施法者脚下蓝白环扩散<br>**持续效果**：受 shield 影响的单位脚下蓝白环呼吸（已在 2.1 "护盾存在"状态里）|
| **召唤** | 飘字 + 召唤弹 | **召唤弹落地**：紫色光柱（加大量 energy_fog 粒子）<br>**骷髅出生**：dissolve 反向出现（紫黑色边缘）+ 脚下紫黑环 |
| **治疗** | 飘字 + HealEffect | **释放瞬间**：施法者头顶**金色十字光环**（扩散 0.3 秒）<br>**治疗目标**：每个目标脚下闪一次金色环 + heal_effect（已有）|
| **驱散** | 飘字 | **释放瞬间**：白色清除波纹（从施法者扩散）<br>**命中目标**：buff 视觉瞬间消失（断开 enraged/blessed 等 shader uniform）|

**通用建议**：
- 技能释放的"瞬间感"由**屏幕级后处理**承担（冲击波/色差），不要在单位上加过量粒子
- 引导类技能（劝化）的"持续感"由**地面 _draw**承担（持续绘制），不要每帧 spawn 粒子
- 释放瞬间加 **screen shake**（轻度 5-8px 偏移，0.2 秒）

## 3. 敌方单位通用模板（次要章节）

敌方单位 22 种，本节只给**类型化模板**。具体单位落到哪个模板，按 `scenes/units/` 里每个场景的特性匹配。

### 模板 A：法师系（火焰/寒冰/风暴/死灵法师）

- **攻击释放**：法术弹道（火球/冰弹/能量球）→ 命中时**元素爆裂粒子**（火=红橙、冰=白蓝、风暴=紫黄、死灵=紫黑）
- **持续状态**：脚下元素能量雾环（弱光，颜色按元素）
- **死亡**：dissolve 消散，边缘色匹配元素色
- **资源未找到**（pyromancer_projectile.tres / cryomancer_projectile.tres）：用**通用能量弹** + tint 替代（shader 控制颜色，复用同一贴图）

### 模板 B：精英/Boss 系（巨魔/石像守卫/铁锤手等大型单位）

- **持续状态**：接入 `boss_glow_enabled`（紫色脉动发光）
- **攻击前摇**：幅度加大（前探 5-6px，比基础兵多 2-3px），蓄力时身体微缩
- **攻击命中**：地面冲击波（小型）+ screen shake（轻度）
- **死亡**：长 dissolve（0.8-1.0 秒）+ 大爆炸 + 强 screen shake
- **HP 阶段切换**（如果有阶段 boss）：每阶段切换时全屏闪白 + 持续 1 秒的红色脉动

### 模板 C：召唤物系（骷髅）

- **出生**：紫色 dissolve 反向 + 紫色光柱
- **持续状态**：脚下淡淡紫黑环（区别于玩家方蓝色）
- **死亡**：直接 dissolve（不加碎片，骨架散架感）+ 小型紫雾粒子

### 模板 D：普通敌方近战/远程

- 复用玩家方基础兵的视觉规则
- 阵营色相关效果（如箭矢 trail）改为敌方色

## 4. 配置说明（用户使用指南）

### 4.1 单位视觉配置

`UnitVisualFeedback` 组件按 `unit_type` 自动选默认配置。只有特殊单位需要在 Inspector 覆盖：

```
attack_lunge_px：        近战前探距离，剑士 3，枪兵 4，弓兵 0
ranged_recoil_px：       远程后坐距离，弓兵 2
hit_push_px：            普通受击位移，默认 2
body_pulse_strength：    攻击/治疗时缩放，0.005 ~ 0.02
status_ring_enabled：    是否显示地面状态环
status_ring_radius：     默认 16-22 px
```

### 4.2 建筑视觉配置

`BuildingActivityVisual` 按 `building_type` 自动选配置。Inspector 可调：

```
activity_anchor：        尘土/地面环的相对位置
pulse_strength：         0.005 ~ 0.020
pulse_interval：         0.5 ~ 1.5 秒
activity_color：         金/蓝白/阵营色
use_dust：               是否使用 Dust 序列帧
use_ground_ring：        是否绘制地面环
```

### 4.3 ParticlePool 配置

`main.gd::_ready()` 启动时预热，配置在 `project_settings.gd` 或 main 的 export 变量：

```
prewarm_counts = {
    "dust": 30,
    "hit_spark": 20,
    "debris": 15,
    "energy_fog": 25,
    "blood_mist": 15,
    "heal_orb": 15,
    "summon_pillar": 10
}
```

跑大规模战斗测试时观察 `push_warning("Particle pool empty: ...")` 日志，按需调大。

### 4.4 后处理 shader 配置

屏幕级后处理（冲击波/色差）需要一个 CanvasLayer：

```
CanvasLayer (layer = 100, 在游戏内容之上 UI 之下)
└─ ColorRect (anchors full rect)
   └─ material = ShaderMaterial (post_process.gdshader)
       └─ shader_parameter/strength = 0  (默认 0，触发时 Tween 0 → peak → 0)
```

**触发 API**（在 `main.gd` 或专门的 `PostProcessController`）：
```gdscript
func shake_screen(strength_px: float = 8.0, duration: float = 0.2) -> void
func chromatic_aberration(strength: float = 0.005, duration: float = 0.2) -> void
func shockwave(center_world: Vector2, max_radius: float = 200.0, duration: float = 0.4) -> void
```
