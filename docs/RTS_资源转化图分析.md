# RTS 资源转化图分析

> 本文是一份独立的 RTS 运营系统分析框架，整合了资源转化图的节点系统、关系系统、反馈环结构、节点/边属性、星际 2 三族案例，以及一个项目分析模板。
>
> 阅读顺序：第一到第五节是分析工具；第六、七节是应用案例；第八节是落地工具；第九节是用本框架诊断一个实际项目的示例。

---

## 引言：为什么用"图"分析 RTS

忘掉兵营、气矿、星轨、水晶塔这些具体名字。它们在系统层面都是**节点**（node），玩家造它们的动作都是**走边**（edge）。

一个 RTS 的运营体验，本质是**一张资源转化图**在玩家脑子里运转时的体验：

- **节点** = 资源池（钱、产能、科技、兵、地盘……）
- **边** = 节点之间的转化（花 150 金造兵营 = `E → P`）
- **环** = 反馈循环（钱 → 开矿 → 更多钱 → 再开矿）
- **属性** = 节点和边各自的设计参数（有界？延迟？可逆？……）

**RTS 的"好玩" = 这张图的结构健康**。图有环、有节奏、有摩擦力，就好玩；图是一条直线、没负面关系、没约束器，就"运营软"。

本文要做的事：把这张图的所有元素系统化，给一份可以用来分析任何 RTS 的工具集。

## 一、节点系统

### 1.1 三类节点角色

节点按在图里扮演的角色分三类：

**表 1-1：节点按角色三分类**

| 角色 | 描述 | 节点 |
|---|---|---|
| **量**（有多少） | 主资源池，参与转化 | E / P / T / A / T2 |
| **上限**（最多多少） | 约束器，只设 cap | S |
| **修饰器**（转化得多好/多快/多准） | 不是池子，是图的参数调节器 | Info / Energy / Morale / AP / Time |

**主资源池是"名词"（图里有什么），元节点是"副词"（图跑得多好），约束器是"天花板"（最多到哪）**。三类角色完全不同，不要混。

### 1.2 主资源池（E/P/T/A/T2）

**表 1-2：五个主资源池**

| 符号 | 名字 | 含义 | 在图里的位置 |
|---|---|---|---|
| **E** | Economy 经济 | 现金流（金币/气） | 流转环的起点 |
| **P** | Production 产能 | 产兵建筑/幼虫池 | E→A 的中转 |
| **T** | Tech 科技 | 解锁等级 | 解锁高级节点 |
| **A** | Army 军力 | 战斗单位总量/质量 | 中转 + 终点 |
| **T2** | Territory 地盘 | 基地/据点数量 | 复利源 |

这 5 个节点是**任何 RTS 的必备**，缺一个就构不成完整环。

### 1.3 约束器（S）

**表 1-3：约束器的本质**

| 符号 | 名字 | 本质 | RTS 必要性 |
|---|---|---|---|
| **S** | Supply 人口 | 只对 A 设天花板，不参与转化 | **可选但强烈建议** |

Supply 不是一个"资源池"，它是**第 1 个约束器**。它不是为了参与转化，是为了**周期性地卡住 A 的增长**，强迫玩家抬头处理它——这就是 RTS 节奏断点的系统来源。

```
【约束器：不参与转化，只设天花板】

                  ┌── cap └──┐
                  ↓          │
    A ─────────────────→  被 S 卡住，停止增长
                                  │
                                  ↓
                         强迫玩家 E→S（补 Depot）
                                  │
                                  ↓
                              cap 提高，A 可继续增长
```

**没有 Supply 的 RTS** = A 单调增长无摩擦，雪球一旦起势不可逆。如果没有 S，必须有替代约束器（Energy 池、Cooldown 等），不能完全没有。

### 1.4 可选元节点

按子品类取舍，每类给定义 + 一个典型 RTS 案例：

**表 1-4：可选元节点候选**

| 候选节点 | 定义 | 典型 RTS 案例 |
|---|---|---|
| **Information**（情报） | 短时高价值的敌方状态信息（兵种/位置/意图） | SC2 隐飞/扫描、帝国时代侦察兵、红警间谍 |
| **Energy**（魔法/能量池） | 单位级别的二级消耗资源，通常带冷却 | 魔兽 3 英雄蓝量、SC2 Ghost 能量、C&C 武器充能 |
| **Morale**（士气/民心） | 群体级别的战斗意愿修正，影响 A 的实际战力 | 全面战争系列（RTS 少见，多用于 RTT） |
| **Action Points**（行动点） | 回合制常见，限制单回合操作数 | RTS 几乎不用；XCOM 类回合制核心 |
| **Time**（季节/回合/时代） | 全局时间维度的阶跃推进 | 帝国时代 4 的时代演进（算半个 Time 节点） |

### 1.5 元节点作为图的修饰器

**元节点不是"第 7 个池子"，是图的修饰器**——它们修改主图的边属性（效率/延迟/触发）或节点属性（质量/损耗），本身不是流转的量。

#### 情报（Information）的修饰位置

**表 1-5：情报效果在图里的位置**

| 玩家直觉 | 在图里的位置 | 修改的属性 |
|---|---|---|
| 选更有利的科技 | E→T 这条边 | Efficiency（效率） |
| 出更针对敌人的兵种 | P→A 这条边 | Efficiency（效率） |
| 降低战损 | A 节点本身 | Decay 系数（死兵率降低） |
| 知道敌人攻击时间，选合理部队 | A 节点的配置 | Trigger（触发条件） |
| 更早开矿 | E→T2 这条边 | Delay（延迟缩短） |
| 更安全的开矿 | E→T2 这条边 | Risk → 确定性提升 |

```
                 ┌─────────── Info（情报）──────────┐
                 │     不是池子，是一组边的修饰器     │
                 ↓                                    ↓
       E ──→ T         E ──→ A         A ──→ T2        E ──→ T2
       效率↑            效率↑           损耗↓           延迟↓
       (选对科技)       (出对兵)        (少死兵)        (更早开矿)
```

#### 其他元节点的修饰角色

**表 1-6：其他元节点的修饰角色**

| 元节点 | 修饰什么 | 本质 |
|---|---|---|
| **Info 情报** | 边的 Efficiency / Delay / 确定性 | 决策质量修正器 |
| **Energy 能量** | 特殊边的 Trigger（充满才能放） | Rate Limiter（速率限制器） |
| **Morale 士气** | A 节点的 Effective 系数 | 节点质量修正器 |
| **Action Points** | 所有主动边的 Rate | 全局速率限制器 |
| **Time 时间** | 所有边的 Rate + Unlock（新边） | 全局阶跃修饰器 |

#### 设计元节点的 5 步方法论

1. 先画主资源池图（E/P/T/A/T2 + 约束器 S）
2. 找出图里"感觉空"的边或节点
3. 问自己：这条边/这个节点缺什么修饰？（效率？延迟？触发？质量？）
4. 选择对应的元节点作为修饰器
5. **元节点本身必须有"获取成本"和"衰减/消耗"**（否则就是免费 buff，没有设计意义）

> **关键洞察 1：节点完整性 = 主资源池（量）+ 约束器（上限）+ 元节点（修饰器）**。三类角色完全不同。设计元节点的正确顺序是**先看主图哪里空，再决定加什么修饰器**，而不是"挑一个酷炫的元节点塞进去"。

## 二、关系系统

### 2.1 三类关系鼎立

图上的边不是同质的。完整的资源图需要 **正面 / 中性 / 负面** 三类关系鼎立——缺负面关系是很多 RTS"运营软"的根因。

### 2.2 完整关系分类表

**表 2-1：资源图关系完整分类**（综合 Adams & Dormans 的经济机制 + Marc LeBlanc 的反馈理论）

| 类别 | 关系 | 符号 | 定义 | 游戏案例 |
|---|---|---|---|---|
| **正面 / 中性** | Convert 转换 | A → B | 花掉 A 得到 B | 100 金 → 1 枪兵 |
| | Catalyst 催化 | A ⇒ B | A 加速 B 的产出速率 | Chrono 让兵营 ×2 |
| | Unlock 解锁 | A ⊃ B | A 是 B 的前置门 | Tier 2 解锁狂热者 |
| | Produce 生产 | ∅ → B | 从虚空/时间生成资源 | 基地每秒产金币、女王注卵 |
| | Trade 交易 | A ↔ B | 双向可逆转化 | 帝国时代市场 100 木 ↔ 75 金 |
| **负面** | Drain 消耗 | A ↯ B | A 持续吃掉 B（维持成本） | 星际 2 矿机有限储量、红警单位耗电 |
| | Inhibit 抑制 | A ⊣ B | A 降低 B 的产出效率（系数） | **魔兽 3 Upkeep**：人口越高金币系数越低 |
| | Block 锁定 | A ✗ B | A 阻止 B 发生 | 科技锁、地形堵路、红警磁暴封锁 |
| | Trade-off 权衡 | A ↑⇅ B ↓ | 得 A 必失 B，零和 | 红警 2 超武 vs 兵营投资的机会成本 |
| | Decay 衰减 | A ⇣ | A 随时间自动减少 | 帝国时代建筑腐蚀、SC2 寄生虫计时 |

**关于 Bottleneck**：很多框架把 Bottleneck（瓶颈）列为一种关系，但这其实是**节点的稀缺性属性**（一个节点 cap 越低、越接近上限，就越容易成为瓶颈），不是两个节点之间的独立关系。Bottleneck 应归到节点属性（见第四节）。

### 2.3 案例：魔兽 3 Upkeep 深度拆解

魔兽争霸 3 的 Upkeep 系统是教科书级的负反馈设计。这里按机制、本质、争议、启示四层拆解。

#### 机制：三档累进税

```
当前人口        产出系数        状态名
──────────────────────────────────────
0 - 30          100%           No Upkeep（无维护）
31 - 60          70%           Low Upkeep（低维护）
61 - 80          40%           High Upkeep（高维护）
```

玩家每采矿 10 金，在 Low Upkeep 下实际只进账 7 金；High Upkeep 下只进账 4 金。

#### 本质：A 反向 Inhibit E

```
   A ↑  ────⊣────→  E 产出系数 ↓
   ↑                     │
   │                     ↓
   └──── E 实际进账 ↓ ───┘
        (因为 E 被 A 抑制)
```

A（军力）的增长通过系数反向 **Inhibit** E（经济）的产出效率。这是典型的负反馈环——领先方被系统反向拉回，落后方相对不受惩罚。

#### 社区争议

- **批评方**：惩罚胜利者；隐性惩罚（新手感知不到）；数值硬（100% → 70% → 40% 缺乏过渡）
- **辩护方**：英雄系统复利太强，没有 Upkeep 雪球会失控；强迫玩家在"爆兵 vs 攒钱升英雄"之间做策略选择

#### 设计启示：设计负反馈的三条原则

1. **让被惩罚方有感知和出路**：UI 上显性提示"你进入了 Low Upkeep"，并给出明确出路（减军力 / 推进结束战斗 / 储蓄后再爆兵）
2. **优先用 softer 手段替代硬税率**：
   - SC2 的解法是**矿机有限储量**（每个矿区矿会用完），扩张的需求自然产生节奏
   - 帝国时代市场的**汇率递减**也是温和的负反馈
   - 共性是**让玩家"自然遇到"而不是"被规则惩罚"**
3. **负反馈要可见、可计算、可规避**：玩家应能说"如果我做 X，Y 会变差 Z"，而不是"我怎么感觉经济变差了"

> **关键洞察 2：没有 Drain/Inhibit/Decay 的 RTS = 没有摩擦力的物理**。正反馈让游戏跑得快，**负反馈才让游戏有起伏、有节奏、有翻盘**。关系完整性 = 正面 + 中性 + 负面三足鼎立。

## 三、反馈环结构

### 3.1 四类典型正反馈环

RTS 之所以好玩，是因为它的资源图里有多个互相咬合的"环"（loop）。以下四类是最典型的正反馈环：

#### 环 1：经济自催生（Snowball Loop）

```
    ┌────────────────────────┐
    ↓                        │
   E ──→ T2 ──→ E ──→ T2 ──→ ...
   金     基     更     再
          地     多     开
                金     矿
```

**钱 → 开矿 → 更多钱 → 再开矿**。RTS 最强的正反馈。一旦启动，雪球越滚越大。

#### 环 2：军力-地盘（Army-Territory Loop）

```
    ┌──────────────────────────┐
    ↓                          │
   E ──→ A ──→ T2 ──→ E ──→ A
   钱    军    占    更    更
         力    领    多    多
               地    钱    兵
```

**钱 → 兵 → 占地 → 更钱 → 更兵**。RTS 的进攻循环，把"军事胜利"转成"经济优势"再转回军事。

#### 环 3：人口压力（Supply Pinch Loop）

```
   A ↑↑↑ ──→ 接近 S ──→ 卡兵 ──→ 强迫 E→S ──→ A 可以继续↑
                                                       │
                                                       ↓
                                                  (循环触发)
```

**军力逼近人口 → 卡兵 → 强迫补 Depot → 解除卡兵 → 军力继续涨 → 再卡**。

这个环**自动产生节奏断点**。每隔 N 秒卡一次，强迫玩家抬头补人口。这就是 RTS 节奏断点的系统来源——它不是凭空设计的，是图里这个环自然涌现的。

#### 环 4：科技-军力（Tech Curve）

```
   E ──→ T ──→ A（质量提升）──→ 战斗胜利 ──→ E ──→ T（更高科技）
```

**钱 → 科技 → 更强兵 → 战斗胜利 → 更钱 → 更科技**。慢但回报高，是 RTS 的长线投资。

### 3.2 环的咬合 = RTS 运营

这四个环不是独立运行的，它们**共享节点**：

```
              ┌─── 环1 经济 ───┐
              ↓                 │
    E ──────→ T2 ←──────────────┘
    │  │      │ ↑
    │  │      │ └── 环2 军力-地盘 ──→ A
    │  ↓      │                     ↑
    │  T ─────┘─────────────────────┘
    │  ↑
    │  └── 环4 科技-军力
    ↓
    P ──→ A ──→ S ←── 环3 人口压力
              ↑
              └── 卡了强迫补 Depot
```

**RTS 的"好玩" = 这四个环在玩家脑子里同时运转**。玩家每时每刻都在**决定推进哪个环**：

- "我现在该开矿（环1）吗？"
- "还是补兵营（环2）？"
- "还是升科技（环4）？"
- "人口快满了，补 Depot（环3）"

> **关键洞察 3：运营决策 = 在四个环之间分配资源**。高手和菜鸟的差距，就是**哪个环什么时候该推**的判断。

### 3.3 用环结构看种族差异

**差异化种族/派系 = 强化不同的环**。不是给不同数值，是给**不同的图结构**。

**表 3-1：SC2 三族强化的环**

| 环 | T 人族 | P 星族 | Z 虫族 |
|---|---|---|---|
| 环1 经济自催生 | 中（Orbital/MULE） | 中（Chrono Nexus） | **强（Hatchery 三合一）** |
| 环2 军力-地盘 | 中（地堡） | **强（Pylon+Warp）** | **强（Creep）** |
| 环3 人口压力 | **强（Depot 升降）** | **强（Pylon 必须先建）** | 弱（Overlord 可飘） |
| 环4 科技-军力 | **强（多 Tech Lab）** | 中（科技线性） | 中（基地升级） |

> **关键洞察 4：差异化种族 = 强化不同的环**。不是给不同数值，是给**不同的图结构**。想做两个派系差异化，**不要调数值，要改图的结构**。

## 四、节点属性与边属性

### 4.1 两类属性必须分开

系统动力学里，**节点（pool）** 和 **边（link）** 的属性是分开建模的。Machinations 这个可视化工具就是这么做的：

- **节点属性**描述资源池本身（存量？有界？有形？……）
- **边属性**描述节点之间的转化（延迟？可逆？速率？……）

混在一起会让设计动作变模糊——设计一个节点和设计一条边是完全独立的两个动作。

### 4.2 节点属性表（5 维）

**表 4-1：节点属性**（描述一个 pool 本身）

| 属性 | 选项 | 含义 | 案例 |
|---|---|---|---|
| **Stock vs Flow**（存量 vs 流量） | 池子 / 每秒变化 | 存量给安全感，流量给紧张感 | 金币 E 是流量为主；科技 T 是存量 |
| **Bounded vs Unbounded**（有界 vs 无界） | 有 cap / 无 cap | 有界 = 必然产生瓶颈断点 | 人口 S 硬上限；金币 E 软上限（堆多浪费） |
| **Tangible vs Intangible**（有形 vs 无形） | 玩家能直接操作 / 抽象层 | 有形 = 心智粒度细，无形 = 抽象 | 军力 A 有形（每个单位可见）；科技 T 无形（Tier 是抽象概念） |
| **Continuous vs Discrete**（连续 vs 离散） | 实数 / 整数或枚举 | 影响心智粒度和数值平衡 | 金币 E 连续；科技 T 离散（I/II/III） |
| **Centralized vs Distributed**（集中 vs 分散） | 全局一个池 / 多个独立池 | 分散 = 注意力压力 | 金币 E 集中；军力 A 分散（每兵独立） |

### 4.3 边属性表（6 维）

**表 4-2：边属性**（描述一条 link）

| 属性 | 选项 | 含义 | 案例 |
|---|---|---|---|
| **Delay**（延迟） | 即时 / 短 / 中 / 长 | 投资回报曲线的形状 | E→A 即时（直接出兵）；E→T 长（升科技） |
| **Reversibility**（可逆性） | 可逆 / 不可逆 | 可逆 = 容错高，不可逆 = 押注 | Trade 可逆；Convert 多半不可逆 |
| **Rate**（速率） | 每 tick 转化多少 | 转化速度 | 1 兵营 = 25 秒/兵；基地 = 1 金/秒 |
| **Efficiency**（效率） | 转化比例 | 资源密度，影响"值得不值得" | 帝国时代市场 100 木 = 75 金（0.75 效率） |
| **Trigger**（触发方式） | 自动 / 主动 / 被动 / 条件 | 玩家心智负担 | 自动（基地每秒产金）；主动（手动造兵）；条件（人口未满才能造） |
| **Determinism**（确定性） | 确定 / 概率 | 心流 vs 赌性 | 多数 RTS 确定；随机产出（如魔兽 3 物品掉落）属概率 |

### 4.4 两类属性的视觉对比

```
   ┌─────────────────┐                     ┌─────────────────┐
   │   节点属性       │                     │   边属性         │
   │ ─────────────   │                     │ ─────────────   │
   │ • 存量 vs 流量   │                     │ • 延迟          │
   │ • 有界 vs 无界   │   ──── 边 ────→     │ • 可逆性        │
   │ • 有形 vs 无形   │                     │ • 速率          │
   │ • 连续 vs 离散   │   ←─── 边 ────      │ • 效率          │
   │ • 集中 vs 分散   │                     │ • 触发方式      │
   └─────────────────┘                     │ • 确定性        │
         (描述 pool)                       └─────────────────┘
                                              (描述 link)

   设计一个节点 = 填左边 5 格
   设计一条边   = 填右边 6 格
   两者完全独立，不要混填
```

> **关键洞察 5：设计一个节点 = 填 5 格；设计一条边 = 填 6 格**。这是设计工具，不是哲学分类——填格子的时候，节点和边完全分开，不要混。

## 五、投资回报曲线

同一个起点 E，对应四条不同的回报曲线：

```
回报
 ↑
 │                              ╱───── T2 开矿（极长延迟，高回报）
 │                            ╱
 │                          ╱
 │             ╱────────── T 升级（长延迟，中回报）
 │           ╱
 │         ╱
 │       ╱
 │     ╱─────────────────── P 兵营（中延迟，中等回报持续）
 │   ╱
 │ ╱────────────────────── A 直接出兵（短延迟，低回报）
 └──────────────────────────────────────→ 时间
```

**表 5-1：四类投资选项**

| 选项 | 节点路径 | 延迟 | 上限回报 | 风险 |
|---|---|---|---|---|
| 直接出兵（150 兵营） | E→P→A | 中 | 中等（持续产出） | 慢 |
| 直接出兵（50 枪兵） | E→A | 短 | 低（一次性） | 战斗死亡 |
| 升级科技 | E→T | 长 | 高（解锁高级） | 中间空窗期 |
| 开分矿 | E→T2 | 极长 | 最高（持续复利） | 中间被压制 |

> **关键洞察 6：RTS 的"决策" = 在不同延迟的回报曲线之间选**。短期 vs 长期，就是这个图。

### 6.2 图例

| 符号 | 关系类型 | 含义 |
|---|---|---|
| `A → B` | Convert | 花掉 A 得到 B |
| `A ⇒ B` | Catalyst | A 加速 B 的产出 |
| `A ⊃ B` | Unlock | A 解锁 B |
| `∅ → B` | Produce | 从虚空/时间生成 |
| `A ↔ B` | Trade | 双向可逆 |
| `A ↯ B` | Drain | A 持续消耗 B |
| `A ⊣ B` | Inhibit | A 抑制 B 的效率 |
| `A ✗ B` | Block | A 阻止 B |
| `A ⇣` | Decay | A 自动衰减 |
| `── cap ──→` | 约束 | 设上限（不是转化） |

### 6.3 阅读这张图的三条建议

1. **先看主资源池环**：E → T2 → E 是经济自催生环；E → A → T2 → E 是军力-地盘环。主环的健康决定运营手感
2. **再看约束器和负面关系**：有没有 S？有没有 Drain/Inhibit/Decay？这些决定图的"摩擦力"
3. **最后看修饰器**：元节点修饰哪些边？这些修饰有没有成本和衰减？

> **关键洞察 7：一张完整的 RTS 资源转化图 = 主资源池流转环 + 约束器 + 正面关系 + 负面关系 + 修饰器**。任何 RTS 都能用这张模板分析——把具体建筑/单位/科技填进对应的节点和边即可。

**表 7-1：三族图结构差异总结**

| 维度 | T 人族 | P 星族 | Z 虫族 |
|---|---|---|---|
| **E 的 Catalyst** | MULE（爆发采矿） | Chrono Nexus（持续加速） | 无（纯 Hatchery 复利） |
| **P 的形态** | 分散（多兵营 + Tech Lab/Reactor） | 分散（多 Gate，Warp Gate 前置） | **单点**（所有 Larva 从 Hatchery 出） |
| **P 的 Catalyst** | Reactor（批量） | Chrono（选择性加速） | **Queen 注卵**（最显性） |
| **S 节点** | Depot 固定但可升降 | Pylon 固定 + 双重作用 | **Overlord 可飘**（最灵活） |
| **T 和 T2 关系** | 分离（Tech Lab ≠ 基地） | 分离（科技建筑 ≠ Nexus） | **耦合**（Hatchery = 基地 + 科技） |
| **负面关系** | 矿区 Decay（隐性） | 弱（无显性 upkeep） | 弱（Creep 反而是正反馈） |
| **可逆性** | **强**（飘建筑、卖建筑、Depot 升降） | 中（Warp Gate 不可逆） | 弱（升级不可逆，兵种变异不可逆） |

**三个关键结论**：

1. **Z 的图最简洁**：Hatchery 三合一让节点最少，玩家心智负担最低，但要求玩家在"操作精度"上补偿（Queen 注卵节奏、Creep 铺设）
2. **P 的图最依赖修饰器**：Chrono 是万能 Catalyst，用好 P 全靠 Chrono 的分配决策——P 玩家的核心技能是"决定催化哪个节点"
3. **T 的图容错最高**：Depot 可升降、建筑可飘、Bunker 可卖——T 的图允许玩家犯错后调整，对应"运营+多线骚扰"的玩法

> **关键洞察 8：SC2 三族的差异本质是图结构差异**。Z 用三合一节点减少节点数（简化图），P 用万能修饰器放大决策深度（丰富图），T 用高可逆性提高容错（柔化图）。**做种族差异 = 改图结构，不是调数值**。

## 八、分析工具

### 8.1 资源关系矩阵

分析任何 RTS 项目，用这张**资源关系矩阵**——横竖都是节点，格子是关系类型：

**表 8-1：通用 RTS 资源关系矩阵模板**

|   | E | P | T | A | T2 | S |
|---|---|---|---|---|---|---|
| **E** | - | Convert | Convert | Convert | Convert | Convert |
| **P** | - | - | - | Convert | - | - |
| **T** | - | Unlock | - | Unlock | - | - |
| **A** | Inhibit\* | - | - | - | Convert\* | - |
| **T2** | Convert | Convert\*\* | - | Convert\*\* | - | Convert |
| **S** | - | - | - | cap | - | - |

\* = A 增长反向 Inhibit E（魔兽 3 Upkeep 式）  
\*\* = Zerg 专属（Hatchery = 产能）

**分析流程**：
1. 填这个矩阵 → 项目的运营图就成型了
2. 每个格子选关系类型（Convert/Catalyst/Unlock/Inhibit/Drain/Decay…）
3. 每个格子选强度（弱/中/强）
4. 检查是否有至少 3 个咬合的环
5. 检查是否有节奏断点（人口/能量/CD）
6. 检查是否有至少 1 条负面关系（Drain/Inhibit/Decay）

### 8.2 设计四问

设计任何运营元素，问这 4 个问题：

#### Q1：这个元素加在了图的哪个节点上？
> 例：加个新建筑「圣坛」 → 加在 E 节点（产水晶，水晶是 E 的子类）

#### Q2：它连了哪些边？什么关系？
> 例：圣坛 E→T（解锁高级兵）、E→A（高级兵需要水晶）、E→T（科技升级要水晶）

#### Q3：它参与哪些环？强化了哪个环？
> 例：圣坛参与环4（科技-军力）—— 通过水晶门槛建立"投资曲线"

#### Q4：它产生节奏断点吗？
> 例：圣坛如果加个"充能"机制（每 30s 可以爆发产一次水晶），就变成节奏断点

4 个问题答完，你就知道这个元素在系统里扮演什么角色。

## 九、项目案例分析：用本框架诊断一个 RTS 项目

这一节示范如何用前面的工具诊断一个**具体项目**。被分析的项目特征：有 E/P/T/A/T2 节点，但 S 和负面关系缺失。

### 9.1 当前矩阵

**表 9-1：项目当前资源关系矩阵**

|   | E | P | T | A | T2 | S |
|---|---|---|---|---|---|---|
| **E** | - | ✅ | ✅ | ✅ | ❌ | ❌ |
| **P** | - | - | - | ✅ | - | - |
| **T** | - | ⚠️ 弱 | - | ✅ | - | - |
| **A** | ❌ | - | - | - | ⚠️ 占领靠走过去 | - |
| **T2** | ✅ 一次性奖励 | ❌ | ❌ | ❌ | - | ❌ |
| **S** | - | - | - | ❌（无人口） | - | - |

### 9.2 盲区诊断

用完整关系清单 + 节点属性表 + 元节点修饰器三件套回看，得到的诊断：

**表 9-2：盲区清单**

| 检查项 | 发现 |
|---|---|
| 主环 | ❌ 缺环1（E→T2→E 断），环2 半通（A→T2 靠走过去），环3 完全无（无 S），环4 扁平（T→P 弱） |
| 约束器 | ❌ Supply 完全缺失，A 增长无摩擦 |
| 负面关系 | ❌ Drain/Inhibit/Decay 全无，扩张单调加速 |
| 节点属性 | ⚠️ 未显式配置（如 T 的 Continuous/Discrete、A 的 Centralized/Distributed） |
| 边属性 | ⚠️ 未显式配置（如 E→T 的 Delay/Reversibility） |
| 修饰器 | ❌ 无 Info/Energy 类修饰器，决策扁平 |

**修正后的诊断**：当前图 = **直线 + 全正面 + 无约束 + 无摩擦**。这不是"运营不够丰富"，是**"系统没有摩擦力"**。

### 9.3 补全优先级

**按以下顺序动手**（从最容易落地、效果最显著的开始）：

1. **先加约束器**：Supply（人口系统）或 Energy（指挥官技能能量池）二选一。这是节奏断点的来源，没有它其他设计都浮在半空
2. **再加 1-2 条 Drain**：最简单的负反馈。比如单位维护费（每秒耗少量金币）、建筑电力消耗。比 Inhibit 数值好调
3. **再加 1 条 Decay**：比如"占领据点有时间限制，超时自动中立化"。强迫玩家持续行动
4. **加修饰器**：Information（侦察）修饰 E→A 效率，让兵种相克显性化；同时情报可作为**软负反馈**（落后方通过侦察翻盘）
5. **最后才考虑加正反馈环**：E→T2→E（开矿复利）是最经典的，但要在 1-4 步落地之后再加，否则雪球会立刻失控

**反过来不要先做的事**：不要先加新建筑/新兵种/新科技。这些是在图结构健康之后才填的内容，图结构本身没搭好之前，加再多内容都是"在直线上挂装饰"。

> **关键洞察 9：先把图的骨架搭对，再往里填内容**。诊断一个 RTS 的运营问题，永远从图结构开始，不要从具体机制开始。结构没搭对之前，加再多机制都是挂在直线上的装饰品。

## 总结

**RTS 运营 = 一张资源转化图 = 三类节点 + 三类关系 + 四类环 + 两类属性**。

- **节点**：主资源池（量：E/P/T/A/T2）+ 约束器（上限：S）+ 元节点（修饰器：Info/Energy/Morale/AP/Time）
- **关系**：正面/中性（Convert/Catalyst/Unlock/Produce/Trade）+ 负面（Drain/Inhibit/Block/Trade-off/Decay）
- **环**：经济自催生 / 军力-地盘 / 人口压力 / 科技-军力
- **属性**：节点属性（5 维）+ 边属性（6 维），分开建模
- **种族差异**：强化不同的环，改图结构不是调数值

**分析任何 RTS 项目的三步法**：

1. 画主资源池图（E/P/T/A/T2 + S）
2. 填资源关系矩阵，检查环、约束器、负面关系是否齐备
3. 用设计四问审视每个新元素

**一个提醒**：这些工具不是用来"一次性设计出完整的图"，而是用来**"诊断当前图的盲区"**。设计时不用 11 个维度全部填满，而是**先保证有节点、有约束器、有正负关系三类、再加 1-2 个环**——图能跑起来之后再精修数值。把工具当诊断器，不要当填表器。

## 附：核心概念速查

| 概念 | 一句话定义 |
|---|---|
| 节点（Node） | 图上的资源池或修饰器 |
| 边（Link） | 节点之间的转化关系 |
| 环（Loop） | 共享节点的多条边形成的反馈循环 |
| 主资源池 | E/P/T/A/T2 五个必备节点 |
| 约束器 | 只设 cap 不参与转化的节点（如 S） |
| 元节点 | 修改边/节点属性的修饰器（如 Info） |
| Convert | 花掉 A 得到 B |
| Catalyst | A 加速 B 的产出 |
| Unlock | A 解锁 B |
| Drain | A 持续消耗 B |
| Inhibit | A 降低 B 的效率 |
| Decay | A 自动衰减 |
| Stock vs Flow | 存量 vs 流量（节点属性） |
| Delay | 转化延迟（边属性） |
| Reversibility | 转化可逆性（边属性） |
